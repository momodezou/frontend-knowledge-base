> **文档定位：** 用于日常知识积累及前端面试复习。优先整理高频、重要、易混淆的语言规则，不把每个语法点拆成单独章节。
>
> **学习建议：** 先独立分析代码输出，再阅读解释；能够讲清“为什么”和实际应用场景，才算真正掌握。

## 一、变量声明与作用域 ⭐⭐⭐

**高频问题：`var`、`let`、`const` 有什么区别？什么是暂时性死区（TDZ）？**

| 对比项 | `var` | `let` | `const` |
| --- | --- | --- | --- |
| 作用域 | 函数作用域 | 块级作用域 | 块级作用域 |
| 声明前访问 | 通常得到 `undefined` | 抛出 `ReferenceError` | 抛出 `ReferenceError` |
| 同一作用域重复声明 | 允许 | 不允许 | 不允许 |
| 重新赋值 | 允许 | 允许 | 不允许 |
| 声明时初始化 | 非必须 | 非必须 | 必须 |

**核心理解：** `var` 声明在创建作用域时就初始化为 `undefined`；`let` 和 `const` 的绑定也在作用域创建时建立，但在执行到声明并初始化之前处于**暂时性死区**。不能简单理解为“`let` 完全不会提升”。

```javascript
console.log(a); // undefined
var a = 10;

// 下面两行是独立示例，若取消注释，会在第一行抛错：
// console.log(b); // ReferenceError
// let b = 20;

const user = { name: 'Tom' };
user.name = 'Jerry'; // 允许修改对象内部属性
// user = {};        // TypeError：不允许重新给变量赋值
```

**经典易错题：**

```javascript
for (var i = 0; i < 3; i++) {
  setTimeout(() => console.log(i), 0);
}
// 依次输出：3 3 3

for (let j = 0; j < 3; j++) {
  setTimeout(() => console.log(j), 0);
}
// 依次输出：0 1 2
```

原因：第一段的回调共享同一个 `i`；第二段在这种 `for` 循环中为每次迭代创建独立的 `j` 绑定。注意这还涉及回调的异步执行时机。

**面试追问：** `const` 能否保证对象不可变？`Object.freeze()` 是否会自动深度冻结对象？（都不能。）

## 二、数据类型与类型判断 ⭐⭐⭐

**7 种原始类型：** `string`、`number`、`boolean`、`undefined`、`null`、`symbol`、`bigint`。数组、普通对象、日期等属于对象类型；函数是可调用对象。

| 判断方式 | 常见用途 | 易错点 |
| --- | --- | --- |
| `typeof` | 判断多数原始类型、识别函数 | `typeof null` 为 `"object"`；数组也是 `"object"` |
| `Array.isArray(value)` | 判断数组 | 更适合处理跨 iframe 等不同运行领域（realm）的数组 |
| `instanceof` | 判断原型链关系 | 不适合直接判断大部分原始值；可受自定义行为影响 |
| `Object.prototype.toString.call(value)` | 查看常见内置类型标签 | 标签可受 `Symbol.toStringTag` 影响 |

```javascript
console.log(typeof null);        // "object"（历史遗留行为）
console.log(typeof undefined);   // "undefined"
console.log(typeof NaN);         // "number"
console.log(typeof 1n);          // "bigint"
console.log(typeof (() => {}));  // "function"
console.log(typeof []);          // "object"
console.log(Array.isArray([]));   // true
```

**`NaN` 是高频陷阱：**

```javascript
console.log(NaN === NaN);           // false
console.log(Number.isNaN(NaN));     // true
console.log(Number.isNaN('hello')); // false（不会先转换）
console.log(isNaN('hello'));        // true（会先尝试转换为数字）
console.log(Object.is(NaN, NaN));   // true
```

`null` 通常用于表达“明确为空”，`undefined` 多用于表达“未赋值或属性不存在”。两者是不同类型，不能完全混为一谈。

**面试追问：** 为什么 `typeof null` 是 `"object"`？什么时候选择 `Number.isNaN()`，而不是全局 `isNaN()`？

## 三、类型转换与相等比较 ⭐⭐⭐

这部分在代码题、表单处理和真实项目中都容易出错。

**牢记三个原则：**

1. **日常比较优先使用 `===`**，避免意外触发隐式转换。
2. `+` 可能执行字符串拼接，`-` 等算术运算通常会尝试将操作数转为数值。
3. 两个对象即使内容完全相同，也不意味着引用相等。

```javascript
console.log('5' + 1);           // "51"
console.log('5' - 1);           // 4
console.log(Number(''));        // 0
console.log(Number(undefined)); // NaN
console.log(Number(null));      // 0

console.log(0 == false);        // true
console.log(0 === false);       // false
console.log(null == undefined);// true
console.log(null == 0);        // false

console.log({} === {});         // false
console.log([] === []);         // false
```

**假值（falsy）需要记住：** `false`、`0`、`-0`、`0n`、`""`、`null`、`undefined`、`NaN`。与直觉不同，**空数组 `[]` 和空对象 `{}` 都是真值**。

```javascript
console.log(Boolean([])); // true
console.log(Boolean({})); // true
console.log([] == false); // true：宽松比较时发生类型转换
console.log([] === false);// false
```

**`||` 和 `??` 的区别在工程中很实用：**

```javascript
const count = 0;
console.log(count || 10); // 10：左侧是假值就取右侧
console.log(count ?? 10); // 0：只有 null / undefined 才取右侧

const name = '';
console.log(name || '访客'); // "访客"
console.log(name ?? '访客'); // ""
```

**面试追问：** `==` 是不是绝对不能用？为什么 `value == null` 有时用来同时判断 `null` 和 `undefined`？（有明确约束时可以有意识地使用，但一般仍优先 `===`。）

## 四、函数、`this` 与闭包基础 ⭐⭐⭐

**高频问题：普通函数与箭头函数主要有哪些区别？**

| 对比点 | 普通函数 | 箭头函数 |
| --- | --- | --- |
| `this` | 主要由调用方式决定 | 从定义时的外层词法环境继承 |
| `arguments` | 有自己的 `arguments` | 没有自己的 `arguments` |
| 用 `new` 调用 | 可构造的普通函数可以 | 不可以 |
| 自身的 `prototype` 属性 | 普通可构造函数通常有 | 没有 |

**`this` 的核心：** 普通函数的 `this` 取决于如何调用，而不是函数定义在哪个对象里。

```javascript
const obj = {
  value: 100,
  getValue() {
    return this.value;
  },
  later() {
    setTimeout(() => {
      console.log(this.value); // 100：箭头函数继承 later 的 this
    }, 0);
  }
};

console.log(obj.getValue()); // 100
obj.later();

const detached = obj.getValue;
// detached() 已经不再以 obj 作为调用者；不要假设仍会得到 100
const bound = obj.getValue.bind(obj);
console.log(bound());        // 100
```

**闭包是什么？** 函数可以访问它定义时所在词法作用域中的变量，即使外层函数已经执行完毕。

```javascript
function createCounter() {
  let count = 0;
  return () => ++count;
}

const counter = createCounter();
console.log(counter()); // 1
console.log(counter()); // 2
```

常见应用：私有状态、函数工厂、防抖与节流。**闭包本身不等于内存泄漏**；不再需要的对象若仍被长期引用，才可能产生多余内存占用。

**面试追问：** `call`、`apply`、`bind` 的区别是什么？箭头函数为什么不能用 `new`？闭包捕获的变量在什么情况下可被回收？

> 复杂的 `this` 绑定、作用域链和闭包原理，后续在独立专题中深入整理。

## 五、对象引用与浅拷贝、深拷贝 ⭐⭐⭐

**高频问题：为什么修改某个变量引用的对象，会影响另一个变量？**

```javascript
const original = { name: 'Tom', profile: { age: 20 } };
const alias = original;
alias.name = 'Jerry';
console.log(original.name); // "Jerry"：两者引用同一个对象
```

**展开运算符和 `Object.assign()` 通常是浅拷贝：**

```javascript
const original = { name: 'Tom', profile: { age: 20 } };
const copy = { ...original };

copy.name = 'Jerry';
copy.profile.age = 30;

console.log(original.name);        // "Tom"
console.log(original.profile.age); // 30：嵌套对象依旧共享引用
```

**深拷贝怎么做？**

- 对支持结构化克隆的数据，可以使用 `structuredClone()`，它支持循环引用和多种内置对象。
- `structuredClone()` 不能直接克隆函数，也不会保留所有对象的自定义行为。
- `JSON.parse(JSON.stringify(value))` 有明显局限：例如会丢失 `undefined` 属性，将 `Date` 转成字符串，不能序列化循环引用和 `BigInt`。

```javascript
const source = { name: 'Tom', profile: { age: 20 } };
const cloned = structuredClone(source);
cloned.profile.age = 30;
console.log(source.profile.age); // 20
```

**面试追问：** 浅拷贝复制后，哪些修改会影响原对象？`structuredClone()` 和 JSON 序列化分别有哪些限制？

## 六、常用数组方法与可变性 ⭐⭐

不仅要知道方法叫什么，还要知道**返回值、是否修改原数组、默认行为和边界条件**。

| 方法 | 主要作用 | 是否直接修改原数组 |
| --- | --- | --- |
| `map()` | 映射得到新数组 | 否（回调仍可能修改被引用的对象） |
| `filter()` | 筛选 | 否 |
| `find()` | 找到第一个匹配项 | 否 |
| `some()` / `every()` | 判断部分 / 全部项是否满足条件 | 否 |
| `reduce()` | 归并运算 | 否（除非回调自行修改数据） |
| `slice()` | 截取并返回新数组 | 否 |
| `splice()` | 删除、插入、替换 | **是** |
| `sort()` / `reverse()` | 排序 / 反转 | **是** |

**高频易错：`sort()` 默认并不是数值升序。**

```javascript
const nums = [2, 10, 3];
console.log(nums.sort()); // [10, 2, 3]：默认按字符串形式比较
console.log(nums);        // [10, 2, 3]：原数组已经改变

const scores = [2, 10, 3];
scores.sort((a, b) => a - b); // 数值升序：[2, 3, 10]
```

**`slice()` 与 `splice()`：**

```javascript
const arr = [1, 2, 3, 4];
console.log(arr.slice(1, 3));  // [2, 3]，原数组不变
console.log(arr.splice(1, 2)); // [2, 3]，原数组变成 [1, 4]
```

**`fill()` 创建对象时容易共享引用：**

```javascript
const list = Array(3).fill([]);
list[0].push(1);
console.log(list); // [[1], [1], [1]]：同一个内部数组

const independent = Array.from({ length: 3 }, () => []);
independent[0].push(1);
console.log(independent); // [[1], [], []]
```

**面试追问：** `map()` 与 `forEach()` 的区别是什么？如何在不改变原数组的情况下排序？（如 `toSorted()`，或复制后再 `sort()`。）

## 七、异步与事件循环：基础必会 ⭐⭐⭐

**高频问题：为什么 `setTimeout(fn, 0)` 不是立即执行？**

同步代码先执行；当前同步任务结束后，环境在适当时机处理微任务，再继续执行后续任务。浏览器中，Promise 的 `.then()` 回调属于微任务，计时器回调属于任务。

```javascript
console.log('A');

setTimeout(() => {
  console.log('D');
}, 0);

Promise.resolve().then(() => {
  console.log('C');
});

console.log('B');

// 输出：A B C D
```

**必须掌握的规则：**

- `new Promise(executor)` 中的执行器会**同步运行**。
- Promise 的 `.then()` 回调不会插入当前同步调用栈，而是在状态满足时以微任务方式执行。
- `async` 函数始终返回 Promise。
- `await` 暂停的是当前 `async` 函数后续代码的执行，**不会阻塞整个 JavaScript 线程**。
- `setTimeout(fn, 0)` 不保证“零延迟”执行回调。

**面试追问：** Promise 已经完成时，为什么 `.then()` 仍异步执行？`await` 后的代码什么时候继续？微任务过多会造成什么影响？

> Promise 组合 API、复杂输出题、浏览器和 Node.js 的调度差异，留给 `Promise.md` 与 `EventLoop.md` 单独展开。
