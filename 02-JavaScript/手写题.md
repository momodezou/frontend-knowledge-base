# JavaScript 高频手写题

> **定位：** 以面试常见实现为主，覆盖“思路、代码、边界与复杂度”。示例优先保证可理解与可运行，**明确哪些是简化版，不能代替原生 API 的完整规范实现**。
>
> **面试优先级：** ⭐⭐⭐｜**关联：** [this](./this.md) · [原型与原型链](./原型与原型链.md) · [Promise](./Promise.md)

## 一、刷手写题的正确方式

每道题按四步回答：**先说输入输出与边界 → 讲解思路 → 写代码 → 说明时间与空间复杂度**。不要只背现成代码；真正重要的是理解闭包、`this`、原型、Promise、引用和循环引用等问题。

> 建议优先掌握：防抖、节流、深拷贝、`new`、`instanceof`、`bind`、`Promise.all`。其余内容按面试岗位再扩展。

## 二、防抖 debounce ⭐⭐⭐

**需求：** 连续触发时，只在最后一次触发后的指定时间执行一次。适合搜索框输入、窗口 resize 后的统一处理。

```js
function debounce(fn, delay = 300) {
  let timer = null;

  function debounced(...args) {
    const ctx = this;
    clearTimeout(timer);
    timer = setTimeout(() => {
      timer = null;
      fn.apply(ctx, args);
    }, delay);
  }

  debounced.cancel = () => {
    clearTimeout(timer);
    timer = null;
  };
  return debounced;
}

// 浏览器：
// const onInput = debounce(event => console.log(event.target.value), 300);
// input.addEventListener('input', onInput);
```

- **核心：** 闭包保存定时器 ID，每次调用取消旧任务。
- **易错：** 箭头函数作为外层包装会失去动态 `this`；组件卸载时应取消待执行任务。
- **复杂度：** 每次调用 O(1) 时间、O(1) 额外空间（不计参数本身）。
- **范围：** 这是**尾缘触发版**；前缘触发、最大等待时间、返回 Promise 等需求需要额外设计。

## 三、节流 throttle ⭐⭐⭐

**需求：** 高频触发时，最多每隔一段时间执行一次。适合滚动、拖拽等需要控制执行频率的场景。

```js
function throttle(fn, interval = 100) {
  let lastTime = -Infinity;

  return function (...args) {
    const now = Date.now();
    if (now - lastTime >= interval) {
      lastTime = now;
      return fn.apply(this, args);
    }
  };
}
```

- **核心：** 记录上一次执行时间，只允许满足时间间隔的调用执行。
- **易错：** 这是**前缘触发、丢弃尾部调用**的简单版本；最后一次调用不一定被执行。
- **复杂度：** 每次调用 O(1) 时间、O(1) 空间。

**高频对比：** 防抖关注“停止触发后执行”，节流关注“持续触发时限制频率”。如果必须执行最后一次，还要实现带 trailing 的节流版本。

## 四、深拷贝 deepClone ⭐⭐⭐

**需求：** 深度复制数组与普通对象，循环引用不会导致无限递归。

```js
function deepClone(value, seen = new WeakMap()) {
  // 这个教学版仅处理数组与普通对象；其他内置对象直接返回引用。
  if (value === null || typeof value !== 'object') return value;

  const isArray = Array.isArray(value);
  const isPlain = Object.getPrototypeOf(value) === Object.prototype ||
                  Object.getPrototypeOf(value) === null;
  if (!isArray && !isPlain) return value;

  if (seen.has(value)) return seen.get(value);

  const result = isArray
    ? new Array(value.length)
    : Object.create(Object.getPrototypeOf(value));
  seen.set(value, result);

  for (const key of Reflect.ownKeys(value)) {
    if (!Object.prototype.propertyIsEnumerable.call(value, key)) continue;
    result[key] = deepClone(value[key], seen);
  }
  return result;
}

const source = { name: 'Ada', child: { age: 20 } };
source.self = source;
const copy = deepClone(source);
copy.child.age = 30;
console.log(source.child.age); // 20
console.log(copy.self === copy); // true
```

- **核心：** 递归复制、`WeakMap` 记录已复制对象以处理循环引用和重复引用。
- **局限：** 这是教学版，只处理普通对象和数组的**可枚举自有属性**，不处理属性描述符、`Date`、`RegExp`、`Map`、`Set`、`ArrayBuffer` 等专用语义；不能当成通用深拷贝库。
- **复杂度：** 对可处理的对象图为 O(n) 时间和 O(n) 额外空间，n 为遍历的对象节点及属性规模。
- **生产建议：** 能满足业务要求时优先使用 `structuredClone()`；仍要了解不支持函数、某些平台对象等限制。

## 五、模拟 `new` 操作符 ⭐⭐⭐

**需求：** 用简单代码解释构造函数创建实例的行为。

```js
function myNew(Ctor, ...args) {
  if (typeof Ctor !== 'function') {
    throw new TypeError('Ctor must be a function');
  }

  const proto = Ctor.prototype;
  const obj = Object.create(
    proto !== null && (typeof proto === 'object' || typeof proto === 'function')
      ? proto
      : Object.prototype
  );
  const result = Ctor.apply(obj, args);
  return result !== null &&
    (typeof result === 'object' || typeof result === 'function')
      ? result
      : obj;
}

function User(name) { this.name = name; }
const user = myNew(User, 'Ada');
console.log(user.name);             // 'Ada'
console.log(user instanceof User); // true
```

- **核心：** 创建对象 → 连接原型 → 用该对象调用函数 → 处理显式返回对象。
- **局限：** 仅用于**可通过普通函数调用的构造函数**；`class`、某些内建构造函数或使用特殊 `new.target` 语义的函数不能被 `Ctor.apply` 等价模拟。若希望支持类构造函数，应使用 `Reflect.construct(Ctor, args)`（它已是接近原生 `new` 的机制）。
- **复杂度：** 包装本身 O(1) 额外工作，不计构造函数执行及参数存储。

## 六、模拟 `instanceof` ⭐⭐⭐

**需求：** 判断某个构造函数的 `prototype` 是否出现在对象的原型链上。

```js
function myInstanceof(value, Ctor) {
  if (typeof Ctor !== 'function') throw new TypeError('Right side must be a function');
  if (value === null || (typeof value !== 'object' && typeof value !== 'function')) {
    return false;
  }
  const target = Ctor.prototype;
  if (target === null || (typeof target !== 'object' && typeof target !== 'function')) {
    throw new TypeError('prototype must be an object');
  }

  let proto = Object.getPrototypeOf(value);
  while (proto !== null) {
    if (proto === target) return true;
    proto = Object.getPrototypeOf(proto);
  }
  return false;
}

function Animal() {}
console.log(myInstanceof(new Animal(), Animal)); // true
console.log(myInstanceof([], Array));             // true
```

- **核心：** 不断通过 `Object.getPrototypeOf` 向上查找。
- **局限：** 简化版不实现 `Symbol.hasInstance` 自定义行为、绑定函数及特殊代理等全部规范细节。
- **复杂度：** O(h) 时间，O(1) 空间，h 为原型链高度。

## 七、模拟 `call`、`apply`、`bind` ⭐⭐⭐

### 1. `call/apply` 的思路

这两者本质上是**指定函数调用时的 `this`**，参数形式不同。对于一般业务和面试讨论，直接使用原生 `Function.prototype.call/apply` 更可靠。

```js
function greet(greeting, punctuation) {
  return `${greeting}, ${this.name}${punctuation}`;
}
const person = { name: 'Ada' };

console.log(greet.call(person, 'Hello', '!'));   // 'Hello, Ada!'
console.log(greet.apply(person, ['Hello', '!'])); // 'Hello, Ada!'
```

**不应把“临时把函数挂在对象属性上再执行”说成完全等价的 polyfill**：遇到 `null/undefined` 接收者、严格模式、不可扩展对象或代理时，它会和原生 `call/apply` 有区别。

### 2. `bind` 的教学版：处理参数预置与 `new` 绑定

```js
function myBind(fn, thisArg, ...preset) {
  function bound(...later) {
    const args = [...preset, ...later];
    if (new.target) {
      return Reflect.construct(fn, args, new.target);
    }
    return Reflect.apply(fn, thisArg, args);
  }

  // 用原型链演示 new 场景中的 instanceof 关系
  if (fn.prototype && typeof fn.prototype === 'object') {
    bound.prototype = Object.create(fn.prototype);
  }
  return bound;
}

function Person(name) { this.name = name; }
const BoundPerson = myBind(Person, { ignored: true }, 'Ada');
const p = new BoundPerson();
console.log(p.name); // 'Ada'
console.log(p instanceof Person); // true
```

- **核心：** 普通调用使用指定的 `this`，构造调用要让新建对象接收初始化结果。
- **局限：** 原生绑定函数在 `.prototype`、`.length`、`.name`、继承和 `Symbol.hasInstance` 等细节还有区别；以上是**教学用近似实现**，不是规范兼容 polyfill。
- **复杂度：** 普通调用 O(k) 组装参数，k 为参数数量。

## 八、函数柯里化 curry ⭐⭐

**需求：** 将 `f(a, b, c)` 改造成能够按阶段接收参数的函数，例如 `f(a)(b)(c)`。

```js
function curry(fn, ...collected) {
  return function (...next) {
    const args = [...collected, ...next];
    return args.length >= fn.length
      ? fn(...args)
      : curry(fn, ...args);
  };
}

const add = (a, b, c) => a + b + c;
const curried = curry(add);
console.log(curried(1)(2)(3)); // 6
console.log(curried(1, 2)(3)); // 6
```

- **核心：** 通过闭包收集已传参数，达到函数形参数量时执行。
- **局限：** 使用 `fn.length` 会受到默认参数、剩余参数等影响；此版不保留原函数动态 `this`。
- **复杂度：** 每次追加参数需要复制已有参数数组，开销与当前参数总数有关。

## 九、实现简化版 `Promise.all` ⭐⭐⭐

**需求：** 输入可迭代的 Promise/普通值；全部成功后按**输入顺序**返回结果，任何一个失败立即拒绝返回的 Promise。

```js
function myPromiseAll(iterable) {
  return new Promise((resolve, reject) => {
    let items;
    try {
      items = Array.from(iterable);
    } catch (error) {
      reject(error);
      return;
    }

    if (items.length === 0) {
      resolve([]);
      return;
    }

    const results = new Array(items.length);
    let remaining = items.length;

    items.forEach((item, index) => {
      Promise.resolve(item).then(value => {
        results[index] = value;
        remaining--;
        if (remaining === 0) resolve(results);
      }, reject);
    });
  });
}

myPromiseAll([
  new Promise(r => setTimeout(() => r('slow'), 20)),
  Promise.resolve('fast'),
  42
]).then(console.log); // ['slow', 'fast', 42]
```

- **核心：** 保留每个输入的 `index`；用计数器判断是否全部完成；把普通值规范化成 Promise。
- **易错：** 不能 `push` 完成值，否则会按完成顺序而不是输入顺序输出；空输入应直接完成。
- **局限：** 这是使用数组快照的教学实现，原生 `Promise.all` 对通用迭代器的逐项消费、异常关闭迭代器等有更完整语义；不应称为百分之百兼容原生。
- **复杂度：** 对 n 项输入，处理及存储 O(n)；不计各异步任务自身复杂度。

## 十、实现简化版 `Promise.race` ⭐⭐

```js
function myPromiseRace(iterable) {
  return new Promise((resolve, reject) => {
    for (const item of iterable) {
      Promise.resolve(item).then(resolve, reject);
    }
  });
}

myPromiseRace([
  new Promise(r => setTimeout(() => r('late'), 30)),
  Promise.resolve('early')
]).then(console.log); // 'early'
```

- **核心：** 第一个 settled 的结果决定新 Promise 的命运。
- **易错：** `race([])` 会永远处于 pending；并不会自动取消其它操作。
- **局限：** 这是简化教学实现；迭代器异常等边界要另外处理。
