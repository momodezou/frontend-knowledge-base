# JavaScript 作用域、执行上下文与闭包

> **定位：** 从词法作用域理解变量查找、执行上下文与闭包，重点解决“为什么输出这个结果”。
>
> **面试优先级：** ⭐⭐⭐｜**前置知识：** [基础知识](./基础知识.md)

## 一、核心概念：先区分三个术语

| 术语 | 核心问题 | 简明理解 |
| --- | --- | --- |
| 词法作用域（Lexical Scope） | 变量**在哪里**能被访问？ | 由代码定义位置决定，不由函数的调用位置决定 |
| 执行上下文（Execution Context） | 代码执行时有哪些运行环境信息？ | 关联词法环境、变量环境、`this` 等信息 |
| 闭包（Closure） | 函数为何能继续访问外部变量？ | 函数与创建时周围词法环境之间的关联 |

需要注意，**作用域链不是运行时复制出来的对象快照**。闭包通常捕获的是绑定，不是创建时变量值的静态副本。

## 二、作用域与变量查找 ⭐⭐⭐

JavaScript 常见作用域包括全局作用域、函数作用域与块级作用域（`let`、`const`）。`var` 在函数内是函数作用域；在普通 `{}` 块中不会形成独立的 `var` 作用域。

```js
const value = 'global';

function outer() {
  const value = 'outer';
  function inner() {
    console.log(value);
  }
  return inner;
}

const fn = outer();
fn(); // 'outer'：看 inner 定义在哪里，不看从哪里调用
```

**面试追问：** 变量查找为什么由定义位置决定？如果同名变量在不同作用域出现，会发生什么？（内层会遮蔽外层。）

## 三、变量提升、TDZ 与执行上下文 ⭐⭐⭐

创建执行上下文时，引擎会处理声明并建立对应的环境记录。通俗地说：

1. `var` 声明在初始化前读取通常得到 `undefined`。
2. 函数声明通常可以在其声明之前调用（具体受作用域和严格模式等规则约束）。
3. `let`、`const` 在作用域内被创建，但初始化前处于暂时性死区（TDZ）。
4. **提升不等于源码被真的移动到文件顶部**，只是描述一种可观察行为的教学模型。

```js
console.log(a); // undefined
var a = 1;

hello(); // 'hi'
function hello() { console.log('hi'); }

// 独立执行下方片段：
// console.log(b); // ReferenceError
// let b = 2;
```

**经典易错：`var` 与 `let` 循环绑定**

```js
for (var i = 0; i < 3; i++) {
  setTimeout(() => console.log(i), 0);
}
// 3、3、3

for (let j = 0; j < 3; j++) {
  setTimeout(() => console.log(j), 0);
}
// 0、1、2
```

`let` 形式的 `for` 循环在每轮迭代中有独立绑定；`var` 版本的回调共享同一个 `i`。不能一概而论成“闭包只会记录最终值”。

## 四、闭包是什么、能做什么 ⭐⭐⭐

闭包使函数在外部函数已经返回后，仍能访问其定义环境中的变量。

### 例 1：私有计数器

```js
function createCounter(initial = 0) {
  let count = initial;
  return {
    increment() { return ++count; },
    get() { return count; }
  };
}

const c1 = createCounter();
const c2 = createCounter(10);
console.log(c1.increment()); // 1
console.log(c1.get());       // 1
console.log(c2.increment()); // 11：独立的词法环境
```

### 例 2：函数工厂和参数预设

```js
function greaterThan(min) {
  return function (value) {
    return value > min;
  };
}

const greaterThan10 = greaterThan(10);
console.log([3, 11, 20].filter(greaterThan10)); // [11, 20]
```

### 例 3：真实项目中的陷阱——“旧值闭包”

闭包不是自动拿到“最新的 UI 状态”。如果回调在某次渲染时创建，可能保留那次渲染中的绑定；在 React Hooks 等场景尤其要考虑依赖与状态更新方式。

```js
function makeLogger() {
  let count = 0;
  const message = `count is ${count}`;
  return {
    inc() { count++; },
    log() { console.log(message); },
    logCurrent() { console.log(`count is ${count}`); }
  };
}

const state = makeLogger();
state.inc();
state.log();        // 'count is 0'：message 是早期生成的字符串
state.logCurrent(); // 'count is 1'：这里重新读取了 count
```

**解释：** 闭包能保留变量绑定；但如果在创建闭包时就把值转换成了另一个不可变字符串，再读取那个字符串，不会自动更新。

## 五、闭包与垃圾回收：最常见的误解

**闭包本身不是内存泄漏。** 只有当不再需要的对象仍然被可达引用链持有，才可能造成多余内存占用。大型缓存、长期监听器、定时器、未清理订阅都值得关注。

```js
function attachHandler(button, largeData) {
  const onClick = () => console.log(largeData.length);
  button.addEventListener('click', onClick);
  return () => button.removeEventListener('click', onClick);
}
// 在组件卸载或业务不再需要时调用返回的清理函数。
```

“外层函数执行结束后所有变量都不会释放”是错误的；引擎可回收不再可达的数据。真正该做的是**移除不再需要的引用与订阅**，而不是避免使用闭包。

## 六、常见面试追问

**Q1：什么是作用域链？**  
A：解析标识符时，先查当前词法环境，再沿外部词法环境逐层查找，直到找到绑定或查找失败。

**Q2：词法作用域与动态作用域的区别？**  
A：JS 采用词法作用域；函数在何处定义决定它访问哪些外层绑定，不因普通调用点改变。

**Q3：闭包是“捕获变量”还是“捕获值”？**  
A：通常关联外层绑定；但闭包可以读取一个早先生成的普通值，产生“旧值”表现。要看具体变量和表达式。

**Q4：闭包的典型应用有哪些？**  
A：封装内部状态、函数工厂、事件处理器、回调与缓存。应用时同时考虑生命周期和清理。

**Q5：`const` 声明的对象为什么还可以修改属性？**  
A：`const` 约束的是绑定不能重新赋值，不会自动冻结对象内部状态。

## 七、必会输出题

先口述结果，再运行验证：

```js
function makeFns() {
  const result = [];
  for (let i = 0; i < 3; i++) {
    result.push(() => i);
  }
  return result;
}
console.log(makeFns().map(fn => fn())); // [0, 1, 2]

let x = 1;
function read() { return x; }
function invoke() {
  let x = 2;
  return read();
}
console.log(invoke()); // 1
```
