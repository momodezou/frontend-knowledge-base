# JavaScript 数据类型与类型转换

> **定位：** 高频基础专题。重点理解“类型是什么、如何判断、何时发生隐式转换”，而不是背诵零散结论。
>
> **面试优先级：** ⭐⭐⭐｜**推荐先修：** [基础知识](./基础知识.md)

## 一、核心知识速览

JavaScript 是动态类型语言，**值有类型，变量可以在运行时指向不同类型的值**。八大类型分为：

- **七种原始类型：** `undefined`、`null`、`boolean`、`number`、`bigint`、`string`、`symbol`。
- **对象类型：** `object`；数组、函数、日期、正则、`Map`、`Set` 等都是对象。函数是可调用对象。

原始值的赋值、参数传递表现为值的复制；对象变量持有的是**引用值**，复制变量不会复制对象本身。JS 只有按值传递，传入对象时传递的是引用值的副本，并不存在另一个“按引用传参”的机制。

```js
let a = 1;
let b = a;
b = 2;
console.log(a); // 1

const x = { score: 1 };
const y = x;
y.score = 2;
console.log(x.score); // 2
```

## 二、类型判断：高频问题

| 手段 | 擅长什么 | 容易出错的地方 |
| --- | --- | --- |
| `typeof` | 判断大多数原始值、函数 | `typeof null === 'object'`，数组是 `'object'` |
| `Array.isArray(value)` | 判断数组 | 应优先于跨窗口场景下的 `instanceof Array` |
| `instanceof` | 检查对象的原型链关系 | 不能泛化为“判断所有类型” |
| `Object.prototype.toString.call(value)` | 查看常见内置类型的标签 | 可被 `Symbol.toStringTag` 自定义，不是绝对可信 |
| `Object.is` | 判断两个值是否相同 | 与 `===` 在 `NaN`、`+0/-0` 上不同 |

```js
console.log(typeof null);         // 'object'
console.log(typeof []);           // 'object'
console.log(typeof (() => {}));   // 'function'
console.log(typeof 1n);           // 'bigint'
console.log(Array.isArray([]));   // true
console.log(Object.is(NaN, NaN)); // true
console.log(NaN === NaN);         // false
console.log(Object.is(+0, -0));   // false
console.log(+0 === -0);          // true
```

**易错：** `typeof undeclaredName` 对不存在的标识符通常返回 `'undefined'`，但对处于暂时性死区（TDZ）的 `let` / `const` 变量执行 `typeof` 仍会抛出 `ReferenceError`。

## 三、`null`、`undefined`、`NaN` 与 `BigInt`

### 1. `null` 和 `undefined`

- `undefined`：常表示未赋值、缺少属性、函数没有显式返回值。
- `null`：通常用于有意识地表达“空值”。
- `null == undefined` 是 `true`，但 `null === undefined` 是 `false`。
- `Number(null)` 是 `0`，`Number(undefined)` 是 `NaN`。

### 2. `NaN`：它仍然是 `number`

```js
console.log(typeof NaN);              // 'number'
console.log(Number.isNaN('hello'));    // false：不做转换
console.log(isNaN('hello'));           // true：先转换，再判断
console.log(Number.isNaN(0 / 0));      // true
```

优先使用 `Number.isNaN()`。不要使用 `value === NaN`：它始终为 `false`。

### 3. `Number` 精度与安全整数

`Number` 使用 IEEE 754 双精度浮点数；日常十进制小数不一定能被二进制精确表示。

```js
console.log(0.1 + 0.2 === 0.3); // false
console.log(Number.isSafeInteger(Number.MAX_SAFE_INTEGER)); // true
console.log(Number.isSafeInteger(Number.MAX_SAFE_INTEGER + 1)); // false

const close = (a, b) => Math.abs(a - b) < Number.EPSILON;
console.log(close(0.1 + 0.2, 0.3)); // true（仅演示小量级）
```

**易错：** `Number.EPSILON` 不是适用于所有数值规模的万能阈值；真实业务应结合数值量级或使用适当的精度模型。金额通常使用以分为单位的整数或专业十进制库。

### 4. `BigInt` 不能和 `Number` 直接混算

```js
console.log(10n + 2n); // 12n
// 10n + 2; // TypeError
console.log(10n === 10); // false
console.log(10n == 10);  // true（不推荐依赖宽松比较）
```

## 四、显式与隐式类型转换

### 1. 显式转换

```js
console.log(String(null));       // 'null'
console.log(Number(''));         // 0
console.log(Number('12px'));     // NaN
console.log(parseInt('12px', 10)); // 12
console.log(Boolean('0'));       // true
console.log(Boolean([]));        // true
console.log(Boolean({}));        // true
```

**假值（falsy）主要有：** `false`、`0`、`-0`、`0n`、`NaN`、`''`、`null`、`undefined`。在浏览器中还有历史特殊值 `document.all`，日常业务不应依赖它。

### 2. 隐式转换：`+` 与其他算术运算

```js
console.log('5' + 1); // '51'：字符串拼接
console.log('5' - 1); // 4：数值运算
console.log(true + 1); // 2
console.log([] + 1);   // '1'
console.log([1, 2] + 3); // '1,23'
```

关键原理：对象参与运算时可能先转换为原始值。具体转换涉及 `Symbol.toPrimitive`、`valueOf()`、`toString()`，不同运算符采用的转换规则不同。不要简单理解为“一切对象都先转为字符串”。

### 3. `==`、`===`、`Object.is()`

```js
console.log(0 == false);         // true
console.log(0 === false);        // false
console.log([] == false);        // true
console.log(Boolean([]));        // true
console.log(null == undefined);  // true
console.log(null == 0);          // false
console.log({} === {});          // false：对象引用不同
```

**面试答法：** 大多数业务代码用 `===`。`==` 在类型不同时可能发生隐式转换；例如 `[] == false` 会将数组转换成原始值，再进行数值比较，而 `Boolean([])` 直接判断对象本身，为 `true`。

### 4. `||` 与 `??`

```js
const pageSize = 0;
console.log(pageSize || 20); // 20：所有假值都会触发右侧
console.log(pageSize ?? 20); // 0：仅 null/undefined 触发右侧
```

表单数字 `0`、空字符串 `''`、布尔值 `false` 都可能是合法值；给默认值时优先明确语义，避免无意覆盖。

## 五、工程实践：容易踩坑的三个场景

1. **接口数据转换：** `Number('') === 0`，所以不能仅靠数值转换成功与否判断输入有效性；先做空值检查。
2. **对象相等：** `a === b` 只比较引用是否相同；需要比较结构时，可按业务字段比对，而不是直接 `JSON.stringify`（属性顺序、特殊值、循环引用都有问题）。
3. **Map 键的比较：** `Map` 使用 SameValueZero 规则，`NaN` 可以作为键；不同对象实例仍是不同的键。

```js
const m = new Map();
m.set(NaN, 'ok');
console.log(m.get(NaN)); // 'ok'
m.set({}, 'first');
console.log(m.get({})); // undefined：不是同一个对象
```
