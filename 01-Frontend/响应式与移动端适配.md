# 响应式与移动端适配：一套页面适应不同屏幕

> **通俗理解**：响应式设计不是把电脑页面等比例缩小，而是根据可用空间调整布局，让内容始终好看、好读、好操作。

## 一、响应式设计到底在解决什么问题？ ⭐⭐⭐

同样是一张商品卡片：

- 大屏：可以一行显示四张。
- 平板：可能一行显示两张。
- 手机：通常一行显示一张，按钮更容易触摸。

**核心思路：内容优先、布局可变。** 不要先死记某台手机宽度，而应根据“页面什么时候开始挤、开始难看”来设置断点。

## 二、正确设置 viewport ⭐⭐⭐

手机浏览器如果没有正确的视口配置，可能按较宽的虚拟页面布局后缩放显示，导致文字很小。

```html
<meta name="viewport" content="width=device-width, initial-scale=1">
```

这表示让布局视口与设备宽度相适应，初始缩放比例为 1。

**注意：** 不建议为了限制缩放而设置 `user-scalable=no`，这可能影响需要放大阅读的用户。

## 三、移动优先与媒体查询 ⭐⭐⭐

移动优先（Mobile First）是指先写窄屏的基础样式，再逐步扩展到宽屏。

```css
.cards {
  display: grid;
  grid-template-columns: 1fr;
  gap: 16px;
}

@media (min-width: 640px) {
  .cards { grid-template-columns: repeat(2, minmax(0, 1fr)); }
}

@media (min-width: 1024px) {
  .cards { grid-template-columns: repeat(4, minmax(0, 1fr)); }
}
```

**为什么使用 `minmax(0, 1fr)`？** 因为长文本、图片等可能让网格项目的最小尺寸过大，设置 0 作为轨道下限更容易避免内容意外撑破布局。

### 高频易错

- 媒体查询一般观察的是**视口**，不是某个卡片自己有多宽。
- 断点不一定是 375/768/1024，应该由内容决定。
- 只在开发者工具里调窄宽度还不够，实际手机上的文字、触摸、浏览器工具栏也要测试。

## 四、CSS 单位怎么选择？ ⭐⭐⭐

| 单位 | 通俗理解 | 常见用途 |
| --- | --- | --- |
| `px` | CSS 像素，不是硬件物理像素 | 边框、固定细节 |
| `%` | 根据相关属性的参考尺寸计算 | 流式宽度 |
| `rem` | 相对根元素字体大小 | 字号和间距体系 |
| `em` | 与当前字体尺寸/属性规则相关 | 组件内部相对尺寸 |
| `vw` | 视口宽度的 1% | 全屏或流体尺寸 |
| `vh` / `dvh` | 视口高度相关 | 满屏区域 |

```css
.hero-title {
  font-size: clamp(1.5rem, 4vw, 3rem);
}
```

`clamp(最小值, 偏好值, 最大值)`：让字号随屏幕变化，但不会无限变大或变小。

### 为什么手机上 100vh 有时不准？

移动浏览器顶部地址栏可能出现或收起，实际可见区域高度随之变化。

```css
.full-screen {
  min-height: 100vh;   /* 兼容性回退 */
  min-height: 100dvh;  /* 动态视口高度 */
}
```

- `svh`：小视口高度，适合保守布局。
- `lvh`：大视口高度。
- `dvh`：动态视口高度，随浏览器界面变化。

**注意：** `dvh` 变化也可能引发布局更新，不适合所有场景。

## 五、让图片在不同设备上清晰且不浪费流量 ⭐⭐⭐

```html
<img
  src="/images/card-800.webp"
  srcset="/images/card-400.webp 400w, /images/card-800.webp 800w"
  sizes="(max-width: 600px) 100vw, 400px"
  width="800"
  height="600"
  alt="产品外观"
>
```

- `srcset`：提供不同尺寸的图片候选。
- `sizes`：告诉浏览器预计展示宽度，帮助选择合适图片。
- `width` / `height`：提供图片宽高比例，帮助减少加载时布局跳动。
- `object-fit: cover`：保持图片比例铺满区域，多余部分可能被裁切。

```css
img { max-width: 100%; height: auto; }
```

### 什么是 DPR？

DPR（设备像素比）可以理解为一个 CSS 像素在设备上对应多少物理像素。高 DPR 屏幕在相同 CSS 展示宽度下可能需要更高分辨率图片，才能保持清晰。

**易错**：不要认为“DPR=2 就要把页面所有 CSS 尺寸乘以 2”。CSS 像素已经是独立的布局单位。

## 六、容器查询：让组件自己适应环境 ⭐⭐

同一个组件可能出现在侧边栏或主区域。只看屏幕宽度，无法准确知道卡片有多少空间。

```css
.product-list { container-type: inline-size; }
.product-card { display: block; }

@container (min-width: 520px) {
  .product-card {
    display: grid;
    grid-template-columns: 160px minmax(0, 1fr);
    gap: 16px;
  }
}
```

**对比：**

- `@media`：主要按视口条件调整整个页面。
- `@container`：根据组件祖先查询容器的条件调整组件内容。

两者可以一起使用。容器查询需要在合适的祖先设置查询容器，而不是在要调整的同一个元素上随意设置。

## 七、移动端开发常见问题 ⭐⭐⭐

| 问题 | 原因/思路 |
| --- | --- |
| 页面出现横向滚动 | 固定宽度、长单词、图片溢出、Flex 项目最小宽度 |
| 点击目标太小 | 增大可交互区域并预留间距 |
| 输入框聚焦时页面抖动 | 软键盘改变可见视口，需在真机测试 |
| iPhone 刘海遮挡按钮 | 考虑安全区域 `env(safe-area-inset-bottom)`，并核对 viewport/设备环境 |
| 字体在不同手机上不一致 | 操作系统字体、字体回退、系统字号设置差异 |
| 横竖屏切换布局异常 | 不要只根据初次加载宽度计算，优先使用 CSS 布局 |

```css
.bottom-action {
  padding-bottom: calc(16px + env(safe-area-inset-bottom, 0px));
}
```

## 八、实战排查步骤

1. 打开 DevTools 的设备模拟，逐渐调整宽度，不只测试某几个固定机型。
2. 检查是否出现横向溢出和文本截断。
3. 检查图片比例、标题换行、按钮点击区域。
4. 检查大字体模式、键盘操作和缩放。
5. 有条件时用真实手机验证地址栏、软键盘和触摸行为。
