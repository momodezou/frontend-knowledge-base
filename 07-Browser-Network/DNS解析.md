# DNS 解析：域名是怎样变成 IP 地址的？

> DNS 可以理解成互联网的电话簿。人更容易记住域名，网络通信通常需要 IP 地址，因此浏览器需要先找到域名对应的 IP。

## 一、DNS 是什么？⭐⭐⭐

DNS 全称 Domain Name System，域名系统。

例如输入：

~~~text
www.example.com
~~~

DNS 帮助查询这个域名对应的 IP 地址，浏览器随后才能向目标服务器建立网络连接。

DNS 的主要任务是名称解析，不负责网页内容传输。

## 二、DNS 为什么采用分层结构？

互联网域名数量巨大，如果所有域名都放在一台服务器上查询，会非常低效，也难以管理。

DNS 采用分层、分布式结构：

- **根域名服务器**：帮助找到顶级域名服务器。
- **顶级域名服务器（TLD）**：例如 .com、.cn 对应的管理层。
- **权威 DNS 服务器**：保存具体域名的 DNS 记录，能够给出最终答案。

例如查询 www.example.com，可能先找到 .com 的服务器，再找到 example.com 的权威服务器。

## 三、DNS 解析过程 ⭐⭐⭐

通常可以这样理解：

1. 浏览器或系统先检查已有 DNS 缓存。
2. 检查本机 hosts 等本地配置。
3. 向配置的递归 DNS 解析器发起查询。
4. 如果递归解析器没有缓存，它会按 DNS 层级查询根、顶级域名和权威服务器。
5. 权威服务器返回记录。
6. 递归解析器把结果返回给客户端，并按 TTL 缓存。

~~~text
浏览器 / 操作系统
       |
       | 查询域名
       v
递归 DNS 解析器
       |
       +---- 根 DNS
       |
       +---- .com 顶级 DNS
       |
       +---- example.com 权威 DNS
       |
       v
返回 IP 地址
~~~

真实环境中可能命中任意一层缓存，因此不一定每次都访问根服务器。

## 四、递归查询与迭代查询

- **递归查询**：客户端希望 DNS 解析器帮忙查到最终答案，解析器负责继续查询。
- **迭代查询**：被询问的 DNS 服务器如果不知道最终答案，通常返回下一步应该询问的服务器线索。

通俗理解：递归是“你帮我查到底”；迭代是“我不知道，但你可以去问下一位”。

## 五、常见 DNS 记录类型 ⭐⭐

| 记录类型 | 作用 |
|---|---|
| A | 域名映射到 IPv4 地址 |
| AAAA | 域名映射到 IPv6 地址 |
| CNAME | 将一个域名别名指向另一个域名 |
| NS | 指定域名由哪些权威 DNS 服务器负责 |
| MX | 邮件服务器记录 |
| TXT | 保存文本信息，常用于域名验证等 |
| SOA | 保存 DNS 区域的权威管理信息 |

注意：CNAME 指向的是另一个域名，不是直接写一个 IP 地址。

## 六、TTL 是什么？

TTL（Time To Live）表示 DNS 记录可以缓存多久。

例如记录 TTL 为 300 秒，递归解析器缓存后，在有效时间内可能直接返回缓存结果。

TTL 的意义：

- TTL 较长：减少重复查询，但 DNS 变更传播到缓存的时间可能更长。
- TTL 较短：缓存更新更灵活，但可能增加查询量。

TTL 不意味着全世界所有缓存会在同一秒自动刷新。不同缓存层和实现会有自己的行为。

## 七、DNS 通常使用 UDP 吗？

传统 DNS 查询通常使用 UDP 53 端口。遇到响应过大、截断或特定场景时也可能使用 TCP 53。

此外还有加密 DNS 方式：

- **DoT**：DNS over TLS。
- **DoH**：DNS over HTTPS。

它们可以加密客户端与解析器之间的 DNS 查询链路，但不代表整个互联网的 DNS 信息都天然保密。

## 八、DNSSEC 是什么？

DNSSEC 通过数字签名帮助验证 DNS 数据的真实性和完整性，降低伪造 DNS 响应的风险。

它不是 DNS 查询加密技术，也不隐藏用户查询了什么域名。

## 九、DNS 与 CDN 有什么关系？

CDN 会把静态资源或内容分发到不同地区的边缘节点。

DNS 解析有时会结合用户所在网络、地理位置、负载等因素，把域名解析到合适的 CDN 节点地址。

因此同一个域名在不同地区或不同时间，可能解析到不同 IP。

## 十、前端开发中如何排查 DNS 问题？

常见现象：

- 网站域名无法解析。
- 某些地区访问失败，其他地区正常。
- DNS 修改后部分用户仍访问旧地址。
- CDN 域名解析结果不符合预期。

可使用：

- 浏览器 DevTools Network：观察请求失败信息。
- nslookup 或 dig：查询 DNS 记录。
- ping：粗略检查网络可达性，但不能证明 HTTP 服务正常。
- traceroute / tracert：分析网络路径（不一定所有节点都响应）。
