# 浏览器事件机制与观察者 API

> 浏览器事件机制可以理解成“消息如何从发生位置传到需要处理它的代码”。除了点击、输入等 DOM 事件，还要掌握事件委托和 Observer 系列 API。

## 一、什么是 DOM 事件？

用户点击按钮、键盘输入、滚动页面，浏览器都会产生相应事件。JavaScript 可以监听事件并执行逻辑：

~~~javascript
const button = document.querySelector("button");

button.addEventListener("click", () => {
  console.log("按钮被点击了");
});
~~~

## 二、事件传播的三个阶段 ⭐⭐⭐

DOM 事件传播通常分为：

1. **捕获阶段（Capturing）**：事件从较外层祖先向目标元素传递。
2. **目标阶段（Target）**：事件到达真正触发事件的目标。
3. **冒泡阶段（Bubbling）**：事件从目标向外层祖先逐级传递。

~~~html
<div id="parent">
  <button id="child">点击</button>
</div>
~~~

~~~javascript
parent.addEventListener("click", () => {
  console.log("parent capture");
}, true);

child.addEventListener("click", () => {
  console.log("child");
});

parent.addEventListener("click", () => {
  console.log("parent bubble");
});
~~~

点击按钮时，通常先执行父元素捕获监听器，再执行目标元素监听器，最后执行父元素冒泡监听器。

第三个参数可以传布尔值，也可以传 options 对象：

~~~javascript
parent.addEventListener("click", handler, {
  capture: true
});
~~~

## 三、事件对象中常见的属性

| 属性 | 含义 |
|---|---|
| target | 事件最初发生的目标元素 |
| currentTarget | 当前正在执行监听器的元素 |
| type | 事件类型，例如 click |
| eventPhase | 当前传播阶段 |
| bubbles | 该事件是否冒泡 |
| cancelable | 是否允许取消默认行为 |
| defaultPrevented | 默认行为是否已被取消 |

最容易混淆的是 target 和 currentTarget：

- target：用户实际点到的元素。
- currentTarget：当前这段监听代码绑定在哪个元素上。

## 四、阻止冒泡、阻止默认行为有什么区别？⭐⭐⭐

- **stopPropagation()**：阻止事件继续向其他节点传播，但不会取消默认行为，也不会阻止当前节点上其他监听器执行。
- **stopImmediatePropagation()**：除了阻止继续传播，还会阻止当前节点上后续注册的监听器执行。
- **preventDefault()**：取消事件对应的默认行为，例如阻止表单默认提交或链接跳转。它不会自动阻止事件冒泡。

~~~javascript
link.addEventListener("click", (event) => {
  event.preventDefault();
  console.log("仍然可以继续冒泡");
});
~~~

**面试记忆：** stopPropagation 是“不再往外传”；preventDefault 是“不执行浏览器默认动作”。

## 五、事件委托（Event Delegation）⭐⭐⭐

事件委托就是把子元素的事件监听放到共同的父元素上，利用事件冒泡处理子元素事件。

~~~html
<ul id="list">
  <li data-id="1"><button>删除</button></li>
  <li data-id="2"><button>删除</button></li>
</ul>
~~~

~~~javascript
const list = document.querySelector("#list");

list.addEventListener("click", (event) => {
  const button = event.target.closest("button");
  if (!button || !list.contains(button)) return;

  const item = button.closest("li");
  console.log("删除数据 ID：", item.dataset.id);
});
~~~

优点：减少大量重复监听器；动态插入的子元素也能被处理；便于统一管理事件。

注意：事件必须能够冒泡，或选择合适的捕获方式；要正确判断实际目标元素，不能假设 event.target 一定是按钮本身。

## 六、addEventListener 的常用选项

~~~javascript
element.addEventListener("click", handler, {
  capture: false,
  once: true,
  passive: true
});
~~~

- capture：是否在捕获阶段监听。
- once：监听器执行一次后自动移除。
- passive：告诉浏览器监听器不会调用 preventDefault，浏览器可据此优化滚动等交互。
- signal：可传入 AbortSignal，便于统一取消监听。

~~~javascript
const controller = new AbortController();

window.addEventListener("resize", onResize, {
  signal: controller.signal
});

controller.abort();
~~~

如果 passive 为 true，再调用 preventDefault 通常不会生效。

## 七、MutationObserver：观察 DOM 变化

MutationObserver 用于观察 DOM 节点变化，例如子节点增删、属性变化和文本变化。

~~~javascript
const target = document.querySelector("#app");

const observer = new MutationObserver((records) => {
  records.forEach((record) => {
    console.log(record.type, record);
  });
});

observer.observe(target, {
  childList: true,
  attributes: true,
  characterData: true,
  subtree: true
});

observer.disconnect();
~~~

常见场景：观察第三方组件是否插入节点、监测某个区域 DOM 结构变化。不要用 MutationObserver 代替正常的数据状态管理。

## 八、IntersectionObserver：观察元素是否进入可视区域

例如图片滚动到屏幕附近时再加载：

~~~javascript
const images = document.querySelectorAll("img[data-src]");

const observer = new IntersectionObserver((entries, observer) => {
  entries.forEach((entry) => {
    if (!entry.isIntersecting) return;

    const image = entry.target;
    image.src = image.dataset.src;
    observer.unobserve(image);
  });
}, {
  root: null,
  rootMargin: "100px",
  threshold: 0
});

images.forEach((image) => observer.observe(image));
~~~

- root：用哪个容器作为观察视口，null 表示浏览器视口。
- rootMargin：扩大或缩小观察区域。
- threshold：可见比例达到什么条件时触发回调。
- isIntersecting：当前目标是否与观察区域相交。

## 九、ResizeObserver：观察元素尺寸变化

~~~javascript
const panel = document.querySelector(".panel");

const observer = new ResizeObserver((entries) => {
  for (const entry of entries) {
    console.log("宽度：", entry.contentRect.width);
    console.log("高度：", entry.contentRect.height);
  }
});

observer.observe(panel);
~~~

它观察的是元素尺寸变化，而不是仅观察浏览器窗口变化。适合图表、编辑器、可复用组件等需要根据自身容器尺寸调整的场景。

注意避免在回调中反复修改被观察元素尺寸，导致循环触发。

## 十、requestAnimationFrame 与 requestIdleCallback

### requestAnimationFrame（rAF）

告诉浏览器：在下一次合适的绘制机会前执行回调，适合动画和与页面绘制同步的更新。

~~~javascript
let start;

function animate(timestamp) {
  if (start === undefined) start = timestamp;

  const progress = Math.min((timestamp - start) / 500, 1);
  box.style.transform = "translateX(" + progress * 200 + "px)";

  if (progress < 1) requestAnimationFrame(animate);
}

requestAnimationFrame(animate);
~~~

### requestIdleCallback（rIC）

让浏览器在空闲时间执行不紧急的任务。它不是所有浏览器环境都同等支持，也不能用来执行必须准时完成的核心逻辑。

~~~javascript
if ("requestIdleCallback" in window) {
  requestIdleCallback(() => {
    console.log("执行非紧急任务");
  }, { timeout: 1000 });
}
~~~
