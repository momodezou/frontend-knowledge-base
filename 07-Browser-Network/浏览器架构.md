# 浏览器架构：浏览器内部是怎么分工的？

> 一句话理解：浏览器不是一个程序从头干到尾，而是多个进程分工合作。这样做主要为了稳定、安全和性能。

## 一、用生活例子理解

把浏览器想象成一家大型餐厅：

- **浏览器主进程**像经理：管理窗口、标签页、地址栏和其他工作进程。
- **渲染进程**像厨师：把网页内容加工成用户看到的页面。
- **网络进程**像采购员：向服务器请求 HTML、CSS、JS、图片等资源。
- **GPU 进程**像显示部门：帮助完成页面图层的合成和显示。
- **其他进程**处理音频、视频、插件等专门任务。

下面主要以 Chromium/Chrome 为例。不同浏览器的内部实现并不完全相同。

## 二、为什么要采用多进程？⭐⭐⭐

假设浏览器只有一个进程：

1. 一个网页里的 JavaScript 死循环，可能拖住整个浏览器。
2. 一个网页崩溃，可能连带所有标签页一起崩溃。
3. 网页代码如果能随意访问浏览器内部资源，安全风险很大。
4. 所有任务挤在一起，难以充分利用多核 CPU。

多进程把不同任务放在不同进程中，降低相互影响。

**面试记忆：多进程主要解决稳定性、安全性和性能隔离问题。**

## 三、浏览器中常见的进程

### 1. 浏览器主进程（Browser Process）

它是浏览器的管理中心，常见职责包括：

- 管理浏览器窗口、标签页和用户界面。
- 管理标签页与渲染进程之间的关系。
- 处理地址栏输入、前进后退、书签等浏览器级操作。
- 协调网络请求、权限、下载等功能。
- 接收渲染进程发来的信息，并协调其他进程。

页面的 DOM 和 CSS 布局不是主进程直接负责的主要工作。

### 2. 渲染进程（Renderer Process）

它负责把网页变成屏幕上的内容，是前端开发最需要理解的进程。

- **Blink**：Chromium 使用的渲染引擎，负责 HTML 解析、样式计算、布局、绘制等。
- **V8**：JavaScript 引擎，负责执行 JavaScript。
- 其他模块：处理 DOM、事件、页面生命周期等。

现代 Chrome 会根据站点隔离等策略分配进程，不应简单记成“每个标签页必定一个进程”。

### 3. 网络进程（Network Process）

负责 DNS 查询、建立连接、发送 HTTP/HTTPS 请求、接收服务器响应，以及管理部分网络缓存与连接复用。

### 4. GPU 进程（GPU Process）

负责协调 GPU 相关任务，例如页面图层合成、硬件加速绘制等。不是所有 CSS 动画都会自动交给 GPU，也不是加上 translateZ(0) 就一定能提升性能。

### 5. 其他进程

浏览器还可能使用音频、视频、插件、扩展、数据存储等专门进程或服务。具体划分会随浏览器版本和平台变化。

## 四、打开网页时，进程之间怎么合作？

1. 用户在地址栏输入网址。
2. 浏览器主进程接收导航操作。
3. 网络进程负责 DNS、连接和 HTTP 请求。
4. 服务器返回 HTML。
5. 浏览器选择合适的渲染进程来处理页面。
6. 渲染进程解析 HTML、CSS，执行 JavaScript，计算布局并绘制页面。
7. 页面需要合成时，相关结果交给合成与 GPU 流程处理。
8. 浏览器主进程负责把页面呈现在标签页窗口中。

~~~text
用户输入 URL
    |
浏览器主进程
    |
    +------ 网络进程 ------ DNS / TCP或QUIC / HTTP请求
    |                              |
    |                           服务器
    |                              |
    +<------------------------- 响应数据
    |
渲染进程：HTML / CSS / JS / Layout / Paint
    |
GPU与合成流程
    |
屏幕显示页面
~~~

真实流程中可能有缓存命中、连接复用、Service Worker、预加载扫描器等分支，不一定每次都完整执行上面的每一步。

## 五、什么是 IPC？

IPC 是 Inter-Process Communication，即进程间通信。

不同进程不能像同一个 JavaScript 函数那样直接访问彼此的内存，因此需要通过受控的通信机制交换消息。

例如主进程通知渲染进程开始导航，渲染进程请求网络进程加载资源，渲染进程把页面状态或崩溃信息通知主进程。

**通俗理解：** 不同部门不能直接翻看对方的工作台，而是通过正式的工单或消息系统沟通。

## 六、什么是站点隔离（Site Isolation）？

站点隔离是一种浏览器安全设计。它尽量把不同站点的页面放在不同渲染进程中，减少恶意页面通过进程漏洞读取其他站点敏感数据的风险。

它和同源策略是不同层次的保护：

- **同源策略**：Web 平台对脚本访问不同源资源的限制规则。
- **站点隔离**：浏览器进程架构层面的安全隔离措施。

## 七、进程和线程有什么区别？

- **进程**：独立运行的程序实例，拥有自己的地址空间和资源。
- **线程**：进程内部执行任务的路径。同一进程中的线程可以共享进程内存。

渲染进程内部可能有主线程、合成线程、栅格化工作线程等。主线程处理 JavaScript、DOM 和大量布局工作，但并非所有渲染工作都只能由主线程完成。
