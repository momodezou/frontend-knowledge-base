# TCP 与 UDP：网络数据是怎样传输的？

> TCP 和 UDP 都属于传输层协议。可以把它们理解为两种送货方式：TCP 更像需要签收、按顺序交付的快递；UDP 更像直接发出的一封封数据包，不保证一定送达。

## 一、TCP/IP 网络分层先了解一下

常见 TCP/IP 四层模型：

| 层级 | 主要职责 | 常见协议或内容 |
|---|---|---|
| 应用层 | 定义应用如何交换数据 | HTTP、DNS、WebSocket |
| 传输层 | 进程之间的数据传输 | TCP、UDP |
| 网络层 | 主机之间寻址和转发 | IP |
| 网络接口层 | 在具体链路上传输数据 | Ethernet、Wi-Fi 等 |

OSI 七层模型是另一种教学划分方式。实际工程中经常使用 TCP/IP 四层模型，不必把两套模型混成一套。

## 二、TCP 是什么？⭐⭐⭐

TCP（Transmission Control Protocol，传输控制协议）是一种面向连接、可靠、有序的字节流传输协议。

它的特点：

- **面向连接**：通信前要建立连接。
- **可靠传输**：通过确认、序号、重传等机制处理丢失。
- **有序交付**：接收端按字节序列重组数据。
- **流量控制**：避免发送方把接收方压垮。
- **拥塞控制**：根据网络状况调整发送速度。

TCP 是字节流，不保留应用层每次 write/send 的消息边界。应用协议需要自己定义消息长度或分隔规则。

## 三、TCP 三次握手 ⭐⭐⭐

建立 TCP 连接时，经典过程是三次握手：

~~~text
客户端                         服务端
   | -------- SYN ----------> |
   | <----- SYN + ACK ------- |
   | -------- ACK ----------> |
   |                           |
             连接建立
~~~

1. 客户端发送 SYN：我想建立连接，并告诉你我的初始序列号。
2. 服务端返回 SYN + ACK：我收到了你的请求，也告诉你我的初始序列号。
3. 客户端返回 ACK：我收到了你的信息。

为什么不是两次？

需要让双方都确认：自己的发送能力和接收能力可用，并且双方初始序列号已被对方确认。第三次确认让服务端知道客户端确实收到了服务端的 SYN。

## 四、TCP 四次挥手 ⭐⭐⭐

经典连接关闭过程：

~~~text
客户端                         服务端
   | -------- FIN ----------> |
   | <-------- ACK ---------- |
   | <-------- FIN ---------- |
   | -------- ACK ----------> |
~~~

1. 客户端发送 FIN：我这边数据发完了。
2. 服务端返回 ACK：知道了。
3. 服务端处理完剩余数据后发送 FIN：我这边也发完了。
4. 客户端返回 ACK：确认关闭。

为什么常说四次？

因为 TCP 是全双工的，两个方向的数据通道可以分别关闭。客户端说“我不再发送”，不代表服务端也已经发送完。

实际抓包中可能出现 ACK 与 FIN 合并等情况，因此不一定总能看到四个独立数据包。

### TIME_WAIT 是什么？

主动关闭连接的一方通常可能进入 TIME_WAIT，等待一段时间，确保最后的 ACK 有机会重传，同时让旧连接中的延迟报文有机会从网络中消失。

不要简单说 TIME_WAIT 就是“连接没关闭”，它是 TCP 正常关闭过程中的状态。

## 五、TCP 如何保证可靠传输？

可以从四个机制理解：

1. **序列号**：给字节编号，接收方知道数据顺序。
2. **确认应答（ACK）**：接收方告诉发送方哪些数据已收到。
3. **超时重传**：一段时间没收到确认，发送方可能重新发送。
4. **校验和**：检测传输中数据是否出现错误。

TCP 还会使用快速重传等机制处理丢包。

## 六、滑动窗口：为什么不用每发一个包就等一次确认？

如果每发送一小段数据都等待确认，网络利用率会很低。

滑动窗口允许发送方在一定范围内连续发送尚未确认的数据。随着确认到达，窗口向前移动，发送方可以继续发送新数据。

可以把它理解成传送带：前面一批货还在路上，后面一批也可以继续发，只要不超过窗口允许的范围。

### 流量控制与拥塞控制的区别

- **流量控制**：关注接收方处理能力，避免接收方来不及接收。
- **拥塞控制**：关注整个网络是否拥堵，避免发送太快导致网络丢包和排队。

## 七、UDP 是什么？⭐⭐⭐

UDP（User Datagram Protocol，用户数据报协议）是一种无连接的数据报协议。

特点：

- 不需要像 TCP 一样先建立连接。
- 不保证数据一定到达。
- 不保证数据按发送顺序到达。
- 不提供 TCP 那样的内置重传和流量控制机制。
- 协议开销较小，适合对实时性要求高、能容忍部分丢包或由应用自行处理可靠性的场景。

常见应用包括 DNS 查询、实时音视频、部分游戏通信等。

## 八、TCP 与 UDP 对比

| 对比 | TCP | UDP |
|---|---|---|
| 连接 | 面向连接 | 无连接 |
| 数据形式 | 字节流 | 数据报 |
| 可靠性 | 提供可靠、有序传输 | 不保证送达和顺序 |
| 重传 | 协议层提供 | 通常由应用自行决定 |
| 流量/拥塞控制 | 有 | 不提供 TCP 那套机制 |
| 典型应用 | HTTP/1.1、HTTP/2、数据库连接 | DNS、实时音视频、QUIC 底层 |

**注意：** UDP 不等于“绝对不可靠”。QUIC 就在 UDP 之上实现了可靠传输、拥塞控制和多路复用等能力。

## 九、HTTP/3 为什么使用 UDP？

HTTP/2 使用 TCP，多路复用虽然解决了 HTTP 层多个请求排队的问题，但 TCP 是一个有序字节流：一个 TCP 包丢失，后续数据可能需要等待重传，影响同一连接上的多个流。

QUIC 基于 UDP 构建自己的可靠传输和流管理机制，可以减少不同流之间的相互阻塞，并集成 TLS 1.3。
