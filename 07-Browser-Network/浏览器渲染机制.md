# 浏览器渲染机制：HTML 和 CSS 如何变成页面？

> 可以把浏览器渲染理解为“把设计说明变成真正的房子”：先读材料，再确定样式和结构，接着计算每个物件的位置，最后绘制并显示。

## 一、浏览器渲染的整体流程 ⭐⭐⭐

~~~text
HTML字节 -> 解析HTML -> DOM树
CSS字节  -> 解析CSS  -> CSSOM树
                  |
           DOM + CSSOM
                  |
               样式计算
                  |
                Layout
                  |
                 Paint
                  |
               Raster
                  |
              Composite
                  |
                屏幕
~~~

这是帮助理解的主线流程。真实浏览器会并行加载资源、增量解析，并根据变化跳过某些阶段，不是每次都从头完整执行。

## 二、解析 HTML，构建 DOM 树

DOM 全称 Document Object Model，文档对象模型。

HTML 是文本，浏览器需要把它解析成一组对象节点，并按照父子关系组织起来。

~~~html
<body>
  <div id="app">
    <h1>你好</h1>
    <p>欢迎学习前端</p>
  </div>
</body>
~~~

可以理解成：

~~~text
document
  |
 body
  |
 div#app
  |------ h1 ------ "你好"
  |
  |------ p ------- "欢迎学习前端"
~~~

JavaScript 操作 DOM，本质上就是通过 DOM API 查询、创建、修改和删除这些节点。

## 三、解析 CSS，构建 CSSOM 树

CSSOM 是 CSS Object Model，即 CSS 对象模型。

浏览器读取 CSS 规则，计算选择器、声明、继承和层叠关系，形成可用于样式计算的数据结构。

~~~css
h1 {
  color: red;
  font-size: 24px;
}
p {
  color: #666;
}
~~~

**通俗理解：** DOM 告诉浏览器“房间里有什么家具”，CSSOM 告诉浏览器“家具是什么颜色、多大、什么样式”。

## 四、DOM 和 CSSOM 形成渲染所需结构

浏览器根据 DOM 节点及计算后的样式，确定哪些内容需要显示。

- display: none 的元素及其子树通常不会进入渲染树。
- visibility: hidden 的元素仍占据布局空间，只是不显示出来。
- DOM 中的 script、head 等非可视节点通常不会作为可见内容绘制。

渲染树并不等于 DOM 树的简单复制，它关注最终需要参与页面可视化呈现的内容。

## 五、Layout（布局，也叫 Reflow）

布局阶段要计算每个可见元素的几何信息：宽度和高度、元素位置、内外边距和边框、文本换行、Flex 和 Grid 布局结果等。

例如容器宽度从 400px 变成 600px，里面的文字可能少换几行，后面的元素位置也可能改变，因此浏览器需要重新计算布局。

**通俗理解：** 先确定每件家具摆在哪里、占多大面积。

## 六、Paint（绘制）

布局确定后，浏览器需要绘制实际视觉效果，例如文字和颜色、背景和边框、阴影、图片、圆角等。

**通俗理解：** 家具位置摆好了，现在开始上色、贴墙纸、画出细节。

## 七、Raster 与 Composite

### Raster（栅格化）

浏览器把绘制指令转换成实际像素。为了提高效率，页面可能被拆成多个区域或图块处理。

### Composite（合成）

浏览器把不同图层或图块按正确顺序组合起来，形成最终画面。合成过程可能使用 GPU 加速。

**注意：** 并不是每个 DOM 元素都对应一个独立 GPU 图层。图层由浏览器根据渲染策略决定，创建过多图层也会消耗内存。

## 八、哪些情况会触发重排和重绘？⭐⭐⭐

### 1. 重排（Reflow / Layout）

重排指重新计算元素的几何布局。常见原因：

- 修改元素宽度、高度、位置、内边距等布局相关样式。
- 添加或删除 DOM 节点。
- 修改文字内容导致换行变化。
- 改变窗口尺寸。
- 某些读取布局信息的操作迫使浏览器同步完成尚未处理的布局。

~~~javascript
const box = document.querySelector(".box");
box.style.width = "500px";
~~~

### 2. 重绘（Repaint）

重绘指元素几何位置没有变化，但视觉外观需要重新绘制。例如只修改背景颜色：

~~~javascript
box.style.backgroundColor = "red";
~~~

通常不需要重新计算元素的位置和尺寸，但需要重新绘制受影响区域。

### 3. 合成（Composite）

如果只是修改某些适合合成处理的属性，例如 transform 或 opacity，浏览器在合适条件下可能只更新合成结果，避免重新布局和绘制。

~~~css
.box {
  transition: transform 0.3s;
}
.box:hover {
  transform: translateX(20px);
}
~~~

**重要：** 不要死记“某属性必然只触发某阶段”。具体行为与浏览器、元素、图层和渲染场景有关，要通过 DevTools 验证。

## 九、什么是布局抖动（Layout Thrashing）？

如果 JavaScript 反复交替读取布局信息和修改样式，浏览器可能被迫多次同步计算布局。

不推荐：

~~~javascript
items.forEach((item) => {
  const width = item.offsetWidth;
  item.style.width = width + 10 + "px";
});
~~~

更好的思路是先集中读取，再集中写入：

~~~javascript
const widths = items.map((item) => item.offsetWidth);
items.forEach((item, index) => {
  item.style.width = widths[index] + 10 + "px";
});
~~~

## 十、如何观察浏览器渲染过程？

Chrome DevTools 中常用：

- **Performance**：录制页面操作，观察 Layout、Paint、脚本执行和长任务。
- **Rendering**：打开 Paint flashing 等可视化辅助功能。
- **Layers**：观察图层信息（不同版本入口可能有所变化）。
- **Elements**：检查元素最终计算样式。
