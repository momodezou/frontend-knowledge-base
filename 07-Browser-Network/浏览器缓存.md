# 浏览器缓存：为什么第二次打开网页会更快？

> 缓存可以理解为把经常使用的东西先放在身边。浏览器缓存的目的，是减少重复下载，节省网络流量，并让页面加载更快。

## 一、浏览器缓存是什么？⭐⭐⭐

浏览器缓存是浏览器或中间缓存系统保存资源副本的机制。

例如第一次访问页面时下载了 logo.png，服务器允许缓存一段时间。第二次访问时，如果缓存仍然有效，浏览器可能直接使用本地文件，不必重新下载。

常见缓存对象：HTML、CSS、JavaScript、图片、字体等静态资源。

## 二、两种核心缓存：强缓存和协商缓存 ⭐⭐⭐

### 1. 强缓存（Fresh Cache）

强缓存的意思是：浏览器判断本地缓存还在有效期内，就直接使用缓存，不必向服务器验证资源是否变化。

主要依赖：

- Cache-Control
- Expires（较旧的方式）

例如服务器返回：

~~~http
Cache-Control: max-age=3600
~~~

意思是该响应在规定的新鲜期内可以直接复用，具体还受其他缓存指令和缓存场景影响。

### 2. 协商缓存（Validation）

缓存过期或需要验证时，浏览器可以向服务器询问：“我手里的文件还是最新的吗？”

常见验证器：

- ETag / If-None-Match
- Last-Modified / If-Modified-Since

如果资源没有变化，服务器返回：

~~~http
HTTP/1.1 304 Not Modified
~~~

304 通常没有资源响应体，浏览器继续使用已有缓存文件。

如果资源已经变化，服务器通常返回新的 200 响应和新内容。

**好记版：**

- 强缓存：不问服务器，直接使用本地副本。
- 协商缓存：问服务器是否有变化；没变化就继续使用本地副本。

## 三、Cache-Control 常见指令 ⭐⭐⭐

| 指令 | 含义 |
|---|---|
| max-age=秒数 | 响应可新鲜使用的时间 |
| no-cache | 可以存储，但使用前需要验证 |
| no-store | 不要存储该响应 |
| public | 允许共享缓存存储，仍受其他规则约束 |
| private | 只允许私有缓存存储，不允许共享缓存存储 |
| must-revalidate | 过期后必须验证，不能随意使用过期响应 |
| immutable | 在新鲜期内资源不会变化，适合带版本号的静态资源 |

### 最容易混淆：no-cache 和 no-store

- **no-cache 不是“不缓存”**，而是允许存储，但使用前要向服务器验证。
- **no-store 才是要求不要存储响应**。

## 四、Expires 与 Cache-Control 的区别

Expires 使用一个绝对时间：

~~~http
Expires: Wed, 25 Nov 2026 10:00:00 GMT
~~~

Cache-Control 的 max-age 使用相对秒数：

~~~http
Cache-Control: max-age=3600
~~~

一般优先使用 Cache-Control。旧的 Expires 在兼容历史系统时仍可能遇到。

## 五、ETag 与 Last-Modified ⭐⭐⭐

### ETag

服务器为资源生成一个版本标识符：

~~~http
ETag: "v123"
~~~

下一次请求时浏览器发送：

~~~http
If-None-Match: "v123"
~~~

服务器比较当前资源的 ETag：

- 一致：返回 304。
- 不一致：返回新的 200 和资源内容。

ETag 可以是内容哈希、版本号或其他标识，不要求一定是文件 MD5。

### Last-Modified

服务器告诉浏览器资源最后修改时间：

~~~http
Last-Modified: Tue, 24 Nov 2026 08:00:00 GMT
~~~

浏览器验证时发送：

~~~http
If-Modified-Since: Tue, 24 Nov 2026 08:00:00 GMT
~~~

如果资源没有更新，服务器可以返回 304。

### 两者怎么选？

ETag 通常能提供更精细的版本判断；Last-Modified 基于时间，精度和文件系统时间等因素可能有限。

当请求同时带有 If-None-Match 和 If-Modified-Since 时，服务器通常优先依据 If-None-Match 判断。

## 六、浏览器缓存大致有哪些位置？

- **Memory Cache**：内存缓存，通常读取快，生命周期受页面和浏览器内存管理影响。
- **Disk Cache**：磁盘缓存，适合保存较持久的资源副本。
- **Service Worker Cache Storage**：由 Service Worker 使用 Cache API 管理的缓存，属于应用可编程控制的缓存。

不要把它们理解成固定、绝对的缓存优先级清单。浏览器会根据资源、请求方式、内存压力和实现策略决定使用哪种缓存。

## 七、前端项目中如何设计缓存策略？⭐⭐⭐

### 1. 带内容哈希的静态资源

例如：

~~~text
app.a8f31c.js
style.91d22.css
~~~

文件内容变化时文件名也变化，可以使用较长缓存时间：

~~~http
Cache-Control: public, max-age=31536000, immutable
~~~

### 2. HTML 入口文件

HTML 通常引用当前版本的 JS/CSS 文件。为了让用户及时拿到新版本，HTML 可以使用较短缓存时间或协商缓存，例如：

~~~http
Cache-Control: no-cache
~~~

这表示允许存储，但使用前验证，不是完全禁止缓存。

### 3. 用户隐私或敏感响应

根据业务和安全要求使用 private、no-store 等策略。不要让含有用户隐私的数据被不合适的共享缓存保存。

## 八、Vary 是什么？

Vary 告诉缓存系统：响应还依赖哪些请求头。

例如：

~~~http
Vary: Accept-Encoding
~~~

表示不同 Accept-Encoding 可能对应不同的响应表示。缓存不能只看 URL 就认为这些响应完全相同。

## 九、Service Worker 和浏览器 HTTP 缓存有什么区别？

Service Worker 可以拦截受其作用域控制的请求，并通过 Cache Storage 自行决定缓存策略。

常见策略：

- Cache First：先查缓存，没命中再请求网络。
- Network First：优先请求网络，失败时回退缓存。
- Stale While Revalidate：先返回缓存，同时在后台更新。

Service Worker 缓存策略由开发者控制，和浏览器自身的 HTTP 缓存不是同一个机制。两者可能同时参与资源获取。
