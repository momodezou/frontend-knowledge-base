## 一、项目介绍

`frontend-knowledge-base` 是一个长期维护的个人技术知识库，以 Web 前端开发为核心，同时逐步扩展到后端开发、算法与数据结构、软件工程、AI 技术及项目实践。

本仓库不仅用于整理技术面试题，更重要的是系统积累技术知识，记录学习过程中的思考、实践经验、问题排查过程和解决方案。

希望通过持续学习、实践、总结和复习，逐步构建完整的个人技术知识体系。

### 建设目标

- **知识积累：** 系统整理前端及相关技术知识，形成结构化知识体系。
- **原理理解：** 不仅记录使用方法，更注重技术原理和底层机制。
- **实践沉淀：** 记录实际开发中的技术方案、代码实现和问题解决经验。
- **算法训练：** 持续积累算法与数据结构知识，提高编程能力。
- **面试准备：** 整理高频技术问题、常见面试题及项目经验。
- **技术拓展：** 持续学习后端、工程化、AI 等新技术。

## 三、文档模板

`_templates` 目录用于维护统一的 Markdown 文档模板，保证知识库的记录格式一致。

| 模板文件 | 主要用途 |
|---|---|
| TEMPLATE-QUESTION.md | 技术知识、概念解析和面试题 |
| TEMPLATE-ALGORITHM.md | 算法题、解题思路、代码与复杂度分析 |
| TEMPLATE-DAILY.md | 每日学习内容、问题记录和成果复盘 |

新增文档时，优先复制对应模板，再填写内容。

## 四、文档编写规范

为了方便长期维护，所有文档尽量遵循以下规范。

### 1. 文件命名

- 优先使用简洁、明确的中文或英文名称。
- 一个文件尽量只记录一个核心知识主题。
- 算法题使用题目名称命名。
- 每日学习记录使用 `YYYY-MM-DD.md` 格式。

### 2. 内容组织

技术知识文档尽量包含：

1. 核心概念
2. 工作原理
3. 详细解析
4. 代码示例
5. 实际应用场景
6. 常见问题
7. 延伸知识
8. 参考资料

算法文档尽量包含：

1. 题目描述
2. 输入与输出
3. 解题思路
4. 代码实现
5. 复杂度分析
6. 易错点
7. 相似题目

### 3. 代码规范

- 代码示例应尽量保证可以运行。
- 标注必要的注释。
- 复杂代码应解释关键实现过程。
- 算法代码尽量使用 JavaScript。
- 不直接复制未经理解的代码。

## 五、Git 提交规范

使用 Git 记录知识库的更新历史。

建议采用以下提交信息规范：

| 类型 | 说明 | 示例 |
|---|---|---|
| docs | 新增或修改技术文档 | docs: add JavaScript closure notes |
| algorithm | 新增或修改算法题 | algorithm: add two sum solution |
| review | 更新复习记录 | review: update Vue knowledge |
| fix | 修正知识或代码错误 | fix: correct event loop explanation |
| refactor | 调整目录或文档结构 | refactor: reorganize knowledge folders |

常用命令：

```bash
git add .
git commit -m "docs: update knowledge notes"
git push origin main
```
