# Vue 组件通信：Props、Emits、v-model、Slots 与跨层级状态

> 学习定位：高频面试 + 组件封装。会选工具，比记住所有 API 更重要。

## 1. 先选通信方式

| 场景 | 优先方案 | 说明 |
| --- | --- | --- |
| 父传子 | Props | 单向数据流、明确组件输入 |
| 子通知父 | Emits | 把业务意图以事件通知父层 |
| 父子双向受控值 | `v-model` | `modelValue` 与 `update:modelValue` 协议 |
| 父传渲染结构 | Slots | 普通/具名/作用域插槽 |
| 祖先传递上下文 | `provide/inject` | 表单/主题/表格上下文 |
| 多页面共享状态 | Pinia | 用户信息、权限、全局偏好 |
| 调用子组件公开能力 | 模板 ref + `defineExpose` | 聚焦输入框、打开弹窗等少量命令式动作 |

**原则**：把状态放在它真正的拥有者那里，不要一上来就引入全局 Store；也不要用全局事件总线掩盖复杂的数据流。

## 2. Props / Emits：单向数据流

```vue
<!-- SearchBox.vue -->
<script setup lang="ts">
const props = defineProps<{ placeholder?: string; disabled?: boolean }>()
const emit = defineEmits<{ search: [keyword: string] }>()
function handleInput(event: Event) {
  emit('search', (event.target as HTMLInputElement).value.trim())
}
</script>

<template>
  <input :placeholder="props.placeholder ?? '搜索'" :disabled="props.disabled" @change="handleInput" />
</template>
```

**高频追问：子组件能改 prop 对象的字段吗？** Vue 的 props 绑定是只读的，但对象/数组的嵌套内容可以被子组件修改到同一个引用上；**技术上可变不等于设计上推荐**。除非明确约定，否则应通过 emits 让父组件管理变更。

## 3. `v-model` 的本质

```vue
<!-- MyInput.vue：适用于 Vue 3 通用协议 -->
<script setup lang="ts">
const props = defineProps<{ modelValue: string }>()
const emit = defineEmits<{ 'update:modelValue': [value: string] }>()
</script>

<template>
  <input :value="props.modelValue" @input="emit('update:modelValue', ($event.target as HTMLInputElement).value)" />
</template>
```

```vue
<!-- Parent.vue -->
<script setup lang="ts">
import { ref } from 'vue'
import MyInput from './MyInput.vue'
const title = ref('初始值')
</script>
<template><MyInput v-model="title" /></template>
```

概念上相当于：`<MyInput :model-value="title" @update:model-value="value => title = value" />`。

Vue 3.4+ 可使用 `defineModel()` 编译宏简化定义，使用前应确认项目的 Vue 版本。Vue 3 也允许多个命名模型，例如 `v-model:visible`。

## 4. Slots：作用域属于谁？

**常见误区**：父组件传入的插槽内容仍在**父组件的作用域**求值。子组件要向该内容提供值，使用作用域插槽。

```vue
<!-- DataList.vue -->
<script setup lang="ts">
const props = defineProps<{ items: string[] }>()
</script>
<template>
  <ul>
    <li v-for="item in props.items" :key="item">
      <slot name="row" :item="item">{{ item }}</slot>
    </li>
  </ul>
</template>
```

```vue
<!-- 使用者 -->
<script setup lang="ts">
import DataList from './DataList.vue'
const items = ['Vue', 'Pinia']
</script>
<template>
  <DataList :items="items">
    <template #row="{ item }"><strong>{{ item }}</strong></template>
  </DataList>
</template>
```

## 5. provide / inject：用于组件树上下文

```ts
// keys.ts
import type { InjectionKey, Ref } from 'vue'
export interface FormContext { disabled: Readonly<Ref<boolean>>; submit: () => void }
export const formKey: InjectionKey<FormContext> = Symbol('form')
```

```ts
// 祖先组件的 setup 中
import { provide, ref, readonly } from 'vue'
import { formKey } from './keys'
const disabled = ref(false)
provide(formKey, { disabled: readonly(disabled), submit: () => console.log('submit') })
```

```ts
// 后代组件的 setup 中
import { inject } from 'vue'
import { formKey } from './keys'
const form = inject(formKey)
if (!form) throw new Error('必须在 FormProvider 内使用')
form.submit()
```

**注意**：`inject` 可返回 `undefined`（没有匹配的祖先提供），不要随意断言一定存在。对于跨页面共享业务数据，Pinia 往往比滥用 `provide/inject` 更清晰。

## 6. 模板 ref 与 `defineExpose`

```vue
<!-- Child.vue -->
<script setup lang="ts">
import { ref } from 'vue'
const input = ref<HTMLInputElement | null>(null)
function focus() { input.value?.focus() }
defineExpose({ focus })
</script>
<template><input ref="input" /></template>
```

父组件可以通过模板 ref 调用暴露的 `focus`，但不要让父层随意控制子组件内部大量状态。需要注意 `<script setup>` 的组件实例默认并非全部公开，`defineExpose` 应在同步 setup 阶段使用。

## 7. 组件设计常见反模式

- **Prop drilling**：多层仅传递一个全局上下文对象，考虑 `provide/inject` 或 Store，但不要过度抽象。
- **过度使用双向绑定**：业务提交和校验应有清晰的事务边界；不是所有字段都要即时通知全局状态。
- **事件命名不规范**：推荐表达业务含义（`save`、`change-page`），而不是泛泛的 `click`。
- **动态事件总线无人清理**：尤其多路由页面可能遗留订阅。Pinia 通常更便于显式管理状态。
- **插槽滥用导致封装不清**：为表格组件设计稳定的 row、toolbar、empty 等插槽契约。
