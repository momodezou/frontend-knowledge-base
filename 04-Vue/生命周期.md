# Vue 生命周期：执行时机、副作用清理与常见误区

> 学习定位：面试高频。重点理解“什么时候读得到 DOM、什么时候订阅、什么时候清理”，不只是背钩子顺序。

## 1. 生命周期是什么？

一个 Vue 组件会经历**创建、挂载、更新、卸载**。Vue 在关键时点提供钩子，以便管理组件副作用，例如获取 DOM、绑定第三方实例、侦听窗口事件和清理定时器。

| 阶段 | Options API | Composition API（Vue 3） | 典型用途 |
| --- | --- | --- | --- |
| 创建前/创建后 | `beforeCreate` / `created` | `setup()` 覆盖大多数初始化工作 | 初始化状态、业务逻辑 |
| 挂载前 | `beforeMount` | `onBeforeMount` | 挂载前检查，较少直接用 |
| 挂载后 | `mounted` | `onMounted` | 访问已挂载 DOM、初始化图表 |
| 更新前 | `beforeUpdate` | `onBeforeUpdate` | 检查更新前 DOM 状态 |
| 更新后 | `updated` | `onUpdated` | 更新后的 DOM 行为（慎用） |
| 卸载前 | `beforeUnmount` | `onBeforeUnmount` | 清理前的收尾 |
| 卸载后 | `unmounted` | `onUnmounted` | 清理监听器、定时器、外部实例 |
| 缓存组件激活/停用 | `activated` / `deactivated` | `onActivated` / `onDeactivated` | `KeepAlive` 状态恢复/暂停 |
| 捕获后代错误 | `errorCaptured` | `onErrorCaptured` | 错误兜底与日志上报 |

**重要区别**：Vue 2 使用 `beforeDestroy` / `destroyed`，Vue 3 使用 `beforeUnmount` / `unmounted`。`KeepAlive` 让组件失活而非普通卸载，因此不要只依赖 `onUnmounted` 管理“页面不可见时暂停”的逻辑。

## 2. `onMounted` 与 DOM

```vue
<script setup lang="ts">
import { ref, onMounted, onUnmounted } from 'vue'

const inputEl = ref<HTMLInputElement | null>(null)

onMounted(() => {
  inputEl.value?.focus() // 组件对应 DOM 已挂载
})

function onResize() { console.log(window.innerWidth) }
onMounted(() => window.addEventListener('resize', onResize))
onUnmounted(() => window.removeEventListener('resize', onResize))
</script>

<template><input ref="inputEl" /></template>
```

**易错点**：

- `setup()` 执行时，组件 DOM 尚未挂载；模板 ref 通常还是 `null`。
- `onMounted` 不保证所有异步组件和整个应用的异步内容均已加载完。
- SSR 服务端渲染时，`onMounted` 不在服务端执行；对 `window`、`document` 的访问应考虑运行环境。

## 3. 数据更新后访问 DOM：`nextTick` 与更新钩子

```vue
<script setup lang="ts">
import { ref, nextTick } from 'vue'
const messages = ref<string[]>([])
const listEl = ref<HTMLUListElement | null>(null)

async function append(text: string) {
  messages.value.push(text)
  await nextTick() // 等待本轮 DOM 更新
  listEl.value?.lastElementChild?.scrollIntoView({ block: 'nearest' })
}
</script>

<template>
  <button @click="append('新消息')">添加</button>
  <ul ref="listEl"><li v-for="(m, i) in messages" :key="i">{{ m }}</li></ul>
</template>
```

`onUpdated` 会在组件 DOM 因响应式变更更新后触发，但**不要在 `onUpdated` 中无条件修改响应式状态**，容易制造更新循环。针对某个状态变化执行 DOM 副作用，通常用 `watch(..., { flush: 'post' })` 或相关操作后 `await nextTick()` 更清晰。

## 4. KeepAlive：activated / deactivated 和卸载不是一回事

在标签页、缓存详情页等场景中，`<KeepAlive>` 会缓存切换出去的组件实例。

```ts
import { onActivated, onDeactivated, onUnmounted } from 'vue'

let interval: ReturnType<typeof setInterval> | undefined
function start() {
  stop()
  interval = setInterval(() => console.log('refresh'), 5000)
}
function stop() {
  if (interval !== undefined) clearInterval(interval)
  interval = undefined
}

onActivated(start)
onDeactivated(stop)
onUnmounted(stop)
```

**注意**：`onActivated` 通常在初次挂载以及从缓存恢复时触发；不要在 `onMounted` 和 `onActivated` 中重复启动同一个轮询而不做去重。

## 5. 真实项目：图表实例的生命周期

复杂管理系统中的 ECharts 经常因为以下问题造成内存或展示问题：

1. DOM 尚未挂载就调用 `echarts.init()`。
2. 多次初始化但未释放旧实例。
3. 容器尺寸变化后没有 `resize()`。
4. 缓存页面失活后仍在频繁请求和渲染。

简化示例（需项目已安装 `echarts`）：

```vue
<script setup lang="ts">
import { ref, onMounted, onUnmounted } from 'vue'
import * as echarts from 'echarts'

const container = ref<HTMLDivElement | null>(null)
let chart: echarts.ECharts | undefined
let observer: ResizeObserver | undefined

onMounted(() => {
  if (!container.value) return
  chart = echarts.init(container.value)
  chart.setOption({ xAxis: { type: 'category', data: ['一', '二'] }, yAxis: { type: 'value' }, series: [{ type: 'bar', data: [12, 25] }] })
  observer = new ResizeObserver(() => chart?.resize())
  observer.observe(container.value)
})

onUnmounted(() => {
  observer?.disconnect()
  chart?.dispose()
  chart = undefined
})
</script>

<template><div ref="container" style="height: 300px" /></template>
```

如果与 `KeepAlive`、`v-show` 等结合，需考虑隐藏时容器尺寸可能为 0，重新激活后应触发 `resize()`。
