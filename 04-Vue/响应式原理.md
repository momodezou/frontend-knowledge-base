# Vue 3 响应式原理：Proxy、依赖收集与调度

> 学习定位：中高级前端高频。要能讲清楚“谁读取了什么属性”“谁修改了什么属性”“谁负责调度重新渲染”，而不是只背三个函数名。

## 1. 响应式系统的核心模型

可以把响应式实现理解成两条路径：

1. **读取时收集依赖**：运行某个响应式副作用（例如组件渲染）时访问 `state.count`，读取操作触发 `track`，记录“这个副作用依赖这个属性”。
2. **写入时触发更新**：修改 `state.count`，写入操作触发 `trigger`，找出相关副作用，由调度器安排执行。

简化路径：

```text
组件渲染 / computed / watchEffect
           │ 读取 state.count
           ▼
Proxy get → track(target, key) → 依赖集合
           │
修改 state.count
           ▼
Proxy set → trigger(target, key) → effect / scheduler
           ▼
       重新计算 / 组件更新
```

**注意**：生产环境的 Vue 响应式实现涉及更细的版本、依赖标记、集合操作等优化。下面是教学模型，不是源码的逐行复刻。

## 2. 手写一个最小响应式模型（教学版）

```ts
// 仅演示一个对象/属性/副作用的最小模型：不包含 cleanup、调度、嵌套 effect 等
const dependencies = new WeakMap<object, Map<PropertyKey, Set<() => void>>>()
let activeEffect: (() => void) | undefined

function track(target: object, key: PropertyKey) {
  if (!activeEffect) return
  let targetMap = dependencies.get(target)
  if (!targetMap) dependencies.set(target, (targetMap = new Map()))
  let dep = targetMap.get(key)
  if (!dep) targetMap.set(key, (dep = new Set()))
  dep.add(activeEffect)
}

function trigger(target: object, key: PropertyKey) {
  dependencies.get(target)?.get(key)?.forEach(fn => fn())
}

function reactive<T extends object>(target: T): T {
  return new Proxy(target, {
    get(obj, key, receiver) {
      track(obj, key)
      return Reflect.get(obj, key, receiver)
    },
    set(obj, key, value, receiver) {
      const oldValue = Reflect.get(obj, key, receiver)
      const result = Reflect.set(obj, key, value, receiver)
      if (result && !Object.is(oldValue, value)) trigger(obj, key)
      return result
    }
  })
}

function effect(fn: () => void) {
  activeEffect = fn
  try { fn() } finally { activeEffect = undefined }
}

const state = reactive({ count: 0 })
effect(() => console.log('render:', state.count)) // render: 0
state.count++ // render: 1
```

**这个最小模型省略了什么？**

- 依赖分支切换后的清理；effect 可能形成旧订阅。
- 嵌套 effect 的执行栈；当前只是单一 `activeEffect`。
- 对象嵌套代理、数组和 `Map`/`Set` 的特殊处理。
- 防止自身递归触发、批处理更新、scheduler、生命周期清理等。

面试中应明确区分**教学示例**和**完整 Vue 源码机制**。

## 3. `reactive`、`ref`、`computed` 的内在差异

- `reactive(obj)` 返回代理对象，读取/写入属性被跟踪。源对象和代理对象的身份通常不同：`reactive(raw) !== raw`。
- `ref(value)` 把值存储在带 `.value` getter/setter 的 ref 对象中；对象类型值通常会被深度转换为响应式代理。
- `computed(getter)` 是具有缓存和脏标记/依赖传播机制的特殊派生 ref：依赖不变时再次读取可复用之前的结果。
- `watch` 需要在依赖变化时调用回调；调度时机与深度遍历取决于选项。

```ts
import { ref, reactive, computed, isReactive } from 'vue'

const raw = { score: 10 }
const proxy = reactive(raw)
console.log(raw === proxy) // false
console.log(isReactive(proxy)) // true

const score = ref(10)
const doubled = computed(() => score.value * 2)
score.value = 12
console.log(doubled.value) // 24
```

## 4. 五个易错边界

### 4.1 解构基本类型字段

```ts
const state = reactive({ count: 1 })
const { count } = state // 得到普通数字 1
state.count++ // count 仍为 1
```

建议：`toRef(state, 'count')` 或 `toRefs(state)`，也可直接访问 `state.count`。Vue 3.5+ 的 `defineProps` 解构存在编译器特殊处理，**不能把它推广到任意 reactive 对象**。

### 4.2 替换代理引用

```ts
import { reactive, ref } from 'vue'
let form = reactive({ name: 'Tom' })
form = reactive({ name: 'Jerry' }) // 先前持有旧 form 的代码不会自动改为新代理

const formRef = ref({ name: 'Tom' })
formRef.value = { name: 'Jerry' } // 更适合整体替换
```

### 4.3 深度代理、浅层代理与标记原始对象

- `reactive()` 通常深度转换对象。
- `shallowReactive()` 仅代理根层属性。
- `shallowRef()` 只在 `.value` 层响应式；适合外部不可变数据或图表实例容器。
- `markRaw()` 可以选择不让特定对象被代理，适合某些第三方类实例；需考虑原始/代理混用导致的身份问题。

### 4.4 数组与集合中 ref 解包不一样

```ts
const r = ref(1)
const obj = reactive({ r })
console.log(obj.r) // 1，深层响应式对象属性会解包

const arr = reactive([ref(1)])
console.log(arr[0].value) // 1，数组元素 ref 需要 .value
```

### 4.5 `watch` 深度侦听不等于快照

```ts
import { reactive, watch } from 'vue'
const settings = reactive({ theme: { dark: false } })
watch(settings, (next, prev) => {
  // 嵌套字段原地变化时，next 和 prev 通常是同一个代理引用
  console.log(next === prev)
})
settings.theme.dark = true
```

如果需要历史数据，对值做明确的快照（例如业务允许时的结构化克隆），并考虑性能。Vue 3.5+ 支持 `deep` 数字限制遍历深度。

## 5. 更新调度与 `nextTick`

Vue 会对组件更新进行批处理，避免同一同步调用栈内多次修改数据就重复做昂贵的 DOM 更新。

```ts
import { ref, nextTick } from 'vue'
const count = ref(0)
async function update() {
  count.value++
  count.value++
  // 响应式值已经是新值，但组件 DOM 不一定已经刷新
  await nextTick()
  // 到这里，本轮队列里的 DOM 更新通常已经完成
}
```

**误区：** `nextTick()` 不是固定等待某个毫秒数，也不是“让所有异步请求都完成”。它等待的是 Vue 更新队列相应刷新时机。
