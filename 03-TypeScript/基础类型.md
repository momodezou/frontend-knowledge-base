# TypeScript 基础类型：高频考点与易错点

> **定位**：理解 TypeScript 如何约束 JavaScript，而不是背语法表。
>
> **重点**：类型推导、`any / unknown / never`、联合类型、数组与元组、空值处理、编译期与运行时的边界。

## 一、TypeScript 究竟解决什么问题？ ⭐⭐⭐

TypeScript 是 JavaScript 的静态类型扩展。它在开发和编译阶段检查类型，帮助发现潜在错误、提供自动补全和重构支持。**大多数 TypeScript 类型注解会在生成 JavaScript 时被擦除，不能当作运行时数据校验。**

```ts
interface User { id: number; name: string }

// 这里的「as User」不会检查接口返回的数据结构
const user = JSON.parse('{"id":"oops","name":"Ada"}') as User;
console.log(typeof user.id); // string，而不是 number
```

**面试回答要点**：静态类型系统提高开发阶段的可维护性，但接口返回值、浏览器存储、用户输入等外部数据，仍应运行时校验。

## 二、基础类型与类型推导 ⭐⭐⭐

| 类型 | 典型写法 | 易错点 |
|---|---|---|
| `string`、`number`、`boolean` | `let age: number = 18` | 使用小写原始类型，不推荐 `Number` 等包装对象类型 |
| 数组 | `number[]` / `Array<number>` | 元素类型需要统一或使用联合类型 |
| 元组 | `[string, number]` | 规定位置和元素类型；普通数组不保留长度与位置关系 |
| 字面量类型 | `'open' \| 'closed'` | 适合限制业务状态 |
| 联合类型 | `string \| null` | 使用前通常需要收窄 |
| `object` | 非原始值 | 不代表“有任意属性的对象” |
| `void` | 不关注返回值 | 不等价于 `undefined` 的所有用途 |
| `never` | 不可能出现的值 | 可用于穷尽检查 |

```ts
let age = 18;            // 推导为 number
const role = 'admin';    // 推导为字面量类型 'admin'
let status: 'idle' | 'loading' | 'success' = 'idle';

const point: [number, number] = [10, 20];
const names: Array<string> = ['Ada', 'Lin'];

function multiply(a: number, b: number) {
  return a * b;         // 返回值通常可推导为 number
}
```

### `as const` 与 `satisfies` 的作用

```ts
const request = {
  method: 'GET',
  timeout: 3000,
} as const;
// method 被推导为只读字面量 'GET'；嵌套字面量也会获得相应的只读类型

type Config = { mode: 'light' | 'dark'; retries: number };
const config = {
  mode: 'dark',
  retries: 2,
} satisfies Config;
// 检查对象是否符合 Config，同时尽量保留表达式自身的推导信息
```

**易错**：`satisfies` 并不会为对象增加运行时检查；`as const` 是类型层面的只读约束，不会对对象调用 `Object.freeze()`。

## 三、`any`、`unknown`、`never` 的本质区别 ⭐⭐⭐

```ts
let unsafe: any = 'hello';
unsafe.notExisting().deep.call(); // 编译器可能不报错；运行时可能出错

let input: unknown = 'hello';
// input.toUpperCase();          // ❌ unknown 不能直接访问属性
if (typeof input === 'string') {
  input.toUpperCase();          // ✅ 收窄后安全
}

function fail(message: string): never {
  throw new Error(message);
}
```

- **`any`**：绕过大部分类型检查，污染后续推导。用于迁移旧项目时应限制范围。
- **`unknown`**：可以接收任意值，但必须验证或收窄后才能安全使用。适合外部输入、异常值。
- **`never`**：表示没有任何可能值，可用于不可达分支、联合类型排除以及穷尽检查。

```ts
function printValue(value: string | number) {
  if (typeof value === 'string') return value.toUpperCase();
  return value.toFixed(2);
}
```

**面试追问**：`any` 和 `unknown` 谁更安全？`never` 和 `void` 是否一样？（不一样：一个表示不会正常获得值，一个表示调用者不关心返回结果。）

## 四、`null`、`undefined` 与可选属性 ⭐⭐⭐

以下规则以 `strictNullChecks: true` 为前提。

```ts
type Profile = {
  nickname?: string;              // 读取时可能得到 undefined
  avatar: string | null;           // 必有这个属性，但值可能为 null
};

function label(profile: Profile): string {
  return profile.nickname ?? '匿名';
}

const p: Profile = { avatar: null };
console.log(label(p)); // 匿名
```

**不要滥用非空断言 `!`**：

```ts
const node = document.querySelector('#app'); // Element | null
// node!.textContent = 'hello'; // 强制断言，运行时仍可能为 null
if (node) node.textContent = 'hello'; // 更安全
```

**易错**：`property?: T` 与 `property: T | undefined` 不完全相同——前者可以缺失，后者要求属性存在（即使值是 `undefined`）。开启 `exactOptionalPropertyTypes` 后，向可选属性显式赋值 `undefined` 的规则也会更严格。

## 五、数组、元组与枚举 ⭐⭐

```ts
const roles: ReadonlyArray<string> = ['admin', 'editor'];
// roles.push('guest'); // ❌ 编译期不允许通过只读引用修改

const tuple: readonly [string, number] = ['Alice', 25];

// 业务状态通常也可以使用字面量联合类型
type OrderStatus = 'pending' | 'paid' | 'cancelled';

// 普通 enum 会生成运行时代码
enum Direction { Up, Down, Left, Right }
console.log(Direction.Up); // 0
```

**选型建议**：

- 纯类型约束、状态枚举：优先考虑字面量联合类型，简洁且不产生额外的枚举运行时代码。
- 需要在运行时访问一组固定常量：可用 `as const` 对象或普通 `enum`。
- `const enum` 可能与某些单文件转译或工具链不兼容，团队采用前应先确认构建约束。

## 六、容易混淆的 `object`、`Object`、`{}` ⭐⭐

```ts
let nonPrimitive: object = { a: 1 };
// nonPrimitive = 123; // ❌ 原始值不能赋给 object

let nonNullish: {} = 123; // ✅ {} 可接收非 null / undefined 的值
// 不要用 {} 表示“空对象”

type EmptyRecord = Record<string, never>;
const empty: EmptyRecord = {};
```

**提示**：`Record<string, never>` 常用于限制普通字符串键属性，但也不是一切运行时“空对象”语义的完美替代；类型系统主要执行结构兼容检查。

## 七、实际工程建议

1. 新项目开启 `strict`，外部数据从 `unknown` 开始验证。
2. 在模块边界（公共 API、导出函数、核心模型）写出清晰类型；局部变量优先利用推导。
3. 用字面量联合表示有限业务状态，用联合类型体现真实的空值可能性。
4. `readonly`、`as const`、`interface` 等不能代替运行时冻结、校验或权限控制。
