# TypeScript 类型守卫：收窄、判别联合和穷尽检查

> **定位**：面试常考的类型守卫，也是业务代码中处理联合类型、外部输入、接口响应的核心工具。

## 一、什么是类型收窄？ ⭐⭐⭐

TypeScript 会结合控制流分析，根据条件判断把某个值在特定代码分支中的类型从“宽”变“窄”。

```ts
function format(value: string | number): string {
  if (typeof value === 'string') return value.trim();
  return value.toFixed(2); // 这里 value 被收窄为 number
}
```

常见收窄手段：`typeof`、`instanceof`、`in`、严格相等比较、`null` 检查、判别联合、自定义类型谓词与断言函数。

## 二、内置类型守卫：`typeof`、`instanceof`、`in` ⭐⭐⭐

```ts
function normalize(value: string | Date): string {
  if (value instanceof Date) return value.toISOString();
  return value.toUpperCase();
}

type Cat = { meow(): void };
type Dog = { bark(): void };
function speak(animal: Cat | Dog) {
  if ('meow' in animal) animal.meow();
  else animal.bark();
}
```

**区别**：

- `typeof` 适用于基本类型检查，但 `typeof null === 'object'`。
- `instanceof` 基于原型链检查；对 JSON 返回的普通对象不能因“形状像某个类”就自动通过类判断。
- `in` 检查属性存在性（也考虑原型链）；**可选属性**可能存在于判断的两侧，需小心。

## 三、判别联合：前端业务建模的高价值技巧 ⭐⭐⭐

```ts
type RequestState<T> =
  | { status: 'idle' }
  | { status: 'loading' }
  | { status: 'success'; data: T }
  | { status: 'error'; message: string };

function renderState(state: RequestState<{ name: string }>): string {
  switch (state.status) {
    case 'idle': return '未开始';
    case 'loading': return '加载中';
    case 'success': return state.data.name;
    case 'error': return state.message;
  }
}
```

**为什么优于一个包含大量可选字段的对象？** 使用判别联合后，`success` 分支一定有 `data`，`error` 分支一定有 `message`；编译器能够检查不合法的状态组合。

## 四、自定义类型守卫 `value is T` ⭐⭐⭐

```ts
type User = { id: number; name: string };

function isUser(value: unknown): value is User {
  if (typeof value !== 'object' || value === null) return false;
  const obj = value as Record<string, unknown>;
  return typeof obj.id === 'number' && typeof obj.name === 'string';
}

function parseUser(json: string): User {
  const raw: unknown = JSON.parse(json);
  if (!isUser(raw)) throw new Error('用户数据格式错误');
  return raw;
}
```

**重要陷阱**：`value is User` 是开发者向编译器作出的**承诺**；编译器不会自动验证守卫函数体是否充分。若检查不完整，类型仍可能不安全。

### 配合 `filter()` 去除空值

```ts
const values: Array<string | undefined> = ['A', undefined, 'B'];
const strings = values.filter((x): x is string => x !== undefined);
// strings: string[]
```

## 五、断言函数与 `never` 穷尽检查 ⭐⭐⭐

```ts
function assertString(value: unknown): asserts value is string {
  if (typeof value !== 'string') throw new TypeError('Expected string');
}

let input: unknown = 'hello';
assertString(input);
input.toUpperCase(); // 此处已经收窄为 string
```

```ts
type Action =
  | { type: 'create'; name: string }
  | { type: 'remove'; id: number };

function assertNever(x: never): never {
  throw new Error('Unhandled action: ' + String(x));
}

function handle(action: Action): string {
  switch (action.type) {
    case 'create': return action.name;
    case 'remove': return String(action.id);
    default: return assertNever(action);
  }
}
```

以后向 `Action` 增加新分支，如果忘记处理，`assertNever(action)` 将在类型检查阶段暴露问题。

## 六、典型易错点 ⭐⭐⭐

### 1. 把“真值判断”当成严格存在性检查

```ts
function describe(value: number | null) {
  if (value) return value.toFixed(0);
  return 'missing or zero'; // 0 会被当作假值
}

function better(value: number | null) {
  if (value !== null) return value.toFixed(0);
  return 'missing';
}
```

### 2. 类型断言 `as` 不会生成校验

```ts
const value: unknown = 'not a number';
const numberValue = value as number;
console.log(typeof numberValue); // 仍然是 string
```

### 3. 属性存在不代表属性值合法

```ts
function isAmount(value: unknown): value is { amount: number } {
  if (typeof value !== 'object' || value === null) return false;
  const obj = value as Record<string, unknown>;
  return typeof obj.amount === 'number' && Number.isFinite(obj.amount);
}
```
