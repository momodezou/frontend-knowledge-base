# TypeScript 工具类型：高频面试与实际业务应用

> **定位**：不死记定义；围绕“已有类型如何变成另一种类型”理解和使用工具类型。

## 一、常见工具类型速查 ⭐⭐⭐

| 工具类型 | 作用 | 典型场景 |
|---|---|---|
| `Partial<T>` | 所有属性可选（浅层） | 表单局部更新、PATCH 参数 |
| `Required<T>` | 所有属性必填（浅层） | 校验完成后的完整模型 |
| `Readonly<T>` | 所有属性只读（浅层） | 避免误修改共享对象 |
| `Pick<T, K>` | 选择部分属性 | 列表 DTO、组件参数 |
| `Omit<T, K>` | 移除部分属性 | 排除密码字段的类型描述 |
| `Record<K, V>` | 构造键值映射 | 状态映射、字典 |
| `Exclude<T, U>` | 联合类型中排除可赋给 U 的成员 | 删除某些状态 |
| `Extract<T, U>` | 联合类型中保留可赋给 U 的成员 | 筛选状态 |
| `NonNullable<T>` | 排除 `null`、`undefined` | 空值过滤后的类型 |
| `ReturnType<F>` | 提取函数返回类型 | 推导 API 结果 |
| `Parameters<F>` | 提取函数参数元组 | 包装函数、透传参数 |
| `Awaited<T>` | 递归提取 Promise 风格的最终值 | async 返回值 |

工具类型只变更**静态类型**，通常不会生成运行时代码。

## 二、对象类型改造：Partial / Required / Readonly ⭐⭐⭐

```ts
interface User {
  id: number;
  name: string;
  profile?: { city: string };
}

type UserUpdate = Partial<User>;
const update: UserUpdate = { name: 'New Name' };

type CompleteUser = Required<User>;
const full: CompleteUser = {
  id: 1,
  name: 'Ada',
  profile: { city: 'Chengdu' },
};

type FrozenUserType = Readonly<User>;
```

**高频易错**：`Partial` 和 `Readonly` 是**浅层**。`Readonly<User>` 只限制属性本身重新赋值，不会自动冻结 `profile.city`。

```ts
interface User { id: number; name: string; profile?: { city: string } }
const obj: Readonly<User> = {
  id: 1, name: 'Ada', profile: { city: 'Chengdu' },
};
if (obj.profile) obj.profile.city = 'Beijing'; // ✅ 嵌套对象未深度只读
```

**另一个易错**：`Required<T>` 处理可选属性的规则会受到编译配置和属性类型影响，不应该代替数据完整性校验。

## 三、字段投影：Pick / Omit ⭐⭐⭐

```ts
interface Employee {
  id: number;
  name: string;
  email: string;
  salary: number;
}

type EmployeeListItem = Pick<Employee, 'id' | 'name'>;
type EmployeePublic = Omit<Employee, 'salary'>;

const item: EmployeeListItem = { id: 1, name: 'Ada' };
```

**安全提醒**：`Omit<Employee,'salary'>` 只改变类型，不会从运行时对象中删除 `salary` 字段；返回给浏览器的敏感信息必须在服务端真实过滤。

## 四、映射类型：Record ⭐⭐⭐

```ts
type Status = 'idle' | 'loading' | 'success' | 'error';
type StatusText = Record<Status, string>;

const statusText: StatusText = {
  idle: '未开始',
  loading: '加载中',
  success: '成功',
  error: '失败',
};
```

**优势**：以后为 `Status` 增加新成员，编译器可以提示映射缺失；对象映射通常比大量 `if/else` 更容易维护。

## 五、联合类型运算：Exclude / Extract / NonNullable ⭐⭐⭐

```ts
type Status = 'idle' | 'loading' | 'success' | 'error';
type Finished = Exclude<Status, 'idle' | 'loading'>;
// 'success' | 'error'

type Active = Extract<Status, 'loading' | 'success'>;
// 'loading' | 'success'

type UserId = string | number | null | undefined;
type ExistingId = NonNullable<UserId>; // string | number
```

**实现原理（简化版）**：

```ts
type MyExclude<T, U> = T extends U ? never : T;
type MyExtract<T, U> = T extends U ? T : never;
```

因为条件类型对裸类型参数的联合类型会发生分布，才可以逐个排除或提取成员。

## 六、函数与异步：ReturnType / Parameters / Awaited ⭐⭐⭐

```ts
function createUser(name: string, age: number) {
  return { id: Date.now(), name, age };
}

type CreatedUser = ReturnType<typeof createUser>;
type CreateUserArgs = Parameters<typeof createUser>; // [name: string, age: number]

type PromiseValue = Awaited<Promise<Promise<{ ok: boolean }>>>;
// { ok: boolean }
```

### 实战：包装函数并保留参数类型

```ts
function logCall<F extends (...args: any[]) => unknown>(fn: F) {
  return (...args: Parameters<F>): ReturnType<F> => {
    console.log('调用参数:', args);
    return fn(...args) as ReturnType<F>;
  };
}

const add = (a: number, b: number) => a + b;
const loggedAdd = logCall(add);
loggedAdd(1, 2); // number
```

上例演示类型提取；更复杂的高阶函数还需要考虑 `this`、重载、异步和异常语义，不应误认为该示例能透明包装所有函数。

## 七、如何避免“滥用工具类型”？ ⭐⭐

- 不要层层套 `Partial<Pick<Omit<...>>>` 让业务模型难以阅读。
- 不要用 `Record<string, any>` 随意绕过检查；更推荐具体键集合或 `unknown`。
- 数据 DTO 应根据真实接口结构命名，必要时显式声明，而不是无限派生。
- `Pick / Omit / Readonly` 无法取代运行时验证、权限控制或对象拷贝。
