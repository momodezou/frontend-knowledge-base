# TypeScript 高级类型：keyof、条件类型、映射类型与 infer

> **定位**：理解“从已有类型生成新类型”的能力；在表格配置、API 类型、组件属性和工具函数中实用，不追求晦涩语法。

## 一、从已有类型获取信息：`keyof`、`typeof`、`T[K]` ⭐⭐⭐

```ts
const user = { id: 1, name: 'Ada', active: true };

type User = typeof user;           // 获取变量的静态类型
type UserKey = keyof User;        // 'id' | 'name' | 'active'
type UserName = User['name'];     // string

function getProp<T, K extends keyof T>(obj: T, key: K): T[K] {
  return obj[key];
}
const username = getProp(user, 'name'); // string
```

| 表达式 | 作用 | 易错点 |
|---|---|---|
| `typeof value`（类型上下文） | 从变量取静态类型 | 与 JS 运行时 `typeof value` 不同 |
| `keyof T` | 提取对象属性键的联合类型 | 索引签名可能扩大为 `string \| number` 等 |
| `T[K]` | 索引访问类型 | K 必须是合法的键类型，且要注意可选属性 |
| `as const` | 保留字面量/只读信息 | 只影响类型检查，不执行运行时冻结 |

### 案例：由常量生成业务状态

```ts
const STATUS = {
  idle: 'idle',
  loading: 'loading',
  done: 'done',
} as const;

type Status = typeof STATUS[keyof typeof STATUS];
// 'idle' | 'loading' | 'done'
```

## 二、条件类型 `T extends U ? X : Y` ⭐⭐⭐

```ts
type IsString<T> = T extends string ? true : false;
type A = IsString<'hello'>; // true
type B = IsString<number>;  // false

type UnwrapArray<T> = T extends Array<infer Item> ? Item : T;
type C = UnwrapArray<string[]>; // string
type D = UnwrapArray<number>;   // number
```

**关键概念**：`extends` 在泛型约束中表示“必须兼容某类型”，在条件类型中用于类型层面的条件判断；它们不是类的运行时继承。

## 三、分布式条件类型：高频易错 ⭐⭐⭐

**当条件类型左侧是“裸类型参数”时**，传入联合类型通常会逐项分发。

```ts
type ToArray<T> = T extends unknown ? T[] : never;
type Distributed = ToArray<string | number>;
// string[] | number[]

type ToArrayTogether<T> = [T] extends [unknown] ? T[] : never;
type NotDistributed = ToArrayTogether<string | number>;
// (string | number)[]
```

理解分布行为是掌握 `Exclude`、`Extract` 等工具类型的基础。

### `never` 不是“普通类型值”

```ts
type Wrap<T> = T extends string ? 'yes' : 'no';
type R = Wrap<never>; // never（没有联合成员可以被分发）
```

如果想判断类型是否为 `never`，常使用元组包装避免分发：

```ts
type IsNever<T> = [T] extends [never] ? true : false;
type R1 = IsNever<never>;   // true
type R2 = IsNever<string>;  // false
```

## 四、`infer`：从类型结构里提取信息 ⭐⭐⭐

```ts
type MyReturnType<T> = T extends (...args: any[]) => infer R ? R : never;
type GetPromiseValue<T> = T extends Promise<infer V> ? V : T;

type Fn = (id: number) => { id: number; name: string };
type Result = MyReturnType<Fn>; // { id: number; name: string }
type Value = GetPromiseValue<Promise<string>>; // string
```

`infer` 只能在条件类型的 `extends` 分支中声明推断变量。复杂 Promise 嵌套拆包通常可直接使用内置 `Awaited<T>`。

## 五、映射类型：批量改造字段 ⭐⭐⭐

```ts
type MakeReadonly<T> = { readonly [K in keyof T]: T[K] };
type MakeOptional<T> = { [K in keyof T]?: T[K] };

type User = { id: number; name: string };
type ReadonlyUser = MakeReadonly<User>;
type PartialUser = MakeOptional<User>;
```

### 映射修饰符与键重映射

```ts
type Mutable<T> = { -readonly [K in keyof T]: T[K] };
type RequiredProps<T> = { [K in keyof T]-?: T[K] };

type GetterMethods<T> = {
  [K in keyof T as K extends string ? `get${Capitalize<K>}` : never]: () => T[K]
};

type User = { id: number; name: string };
type UserGetters = GetterMethods<User>;
// { getId: () => number; getName: () => string }
```

**实际价值**：生成表单字段、字段只读版本、组件事件名称、接口适配层类型等。

## 六、模板字面量类型与复杂度控制 ⭐⭐

```ts
type Field = 'name' | 'age';
type EventName = `on${Capitalize<Field>}Change`;
// 'onNameChange' | 'onAgeChange'

type HttpMethod = 'get' | 'post';
type Action = `${HttpMethod}:${'user' | 'order'}`;
// 'get:user' | 'get:order' | 'post:user' | 'post:order'
```

**易错**：多个大型联合类型在模板字面量中组合会使类型数量快速增加；如果类型表达式开始变得难维护，应该考虑简化业务抽象，而不是继续“类型体操”。

## 七、实战：安全的表格列配置 ⭐⭐⭐

```ts
type Column<T> = {
  [K in keyof T]-?: {
    key: K;
    title: string;
    render?: (value: T[K], row: T) => string;
  }
}[keyof T];

type Employee = { id: number; name: string; active: boolean };

const columns: Column<Employee>[] = [
  { key: 'name', title: '姓名', render: (value) => value.toUpperCase() },
  { key: 'active', title: '状态', render: (value) => value ? '启用' : '停用' },
];
// render(value) 会根据 key 精确推导成对应属性类型
```

这种映射后再索引的写法可保留 `key` 与 `render` 参数之间的对应关系，比简单的 `keyof T` + `T[keyof T]` 更精准。
