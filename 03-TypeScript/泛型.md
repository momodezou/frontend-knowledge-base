# TypeScript 泛型：从类型复用到业务建模

> **定位**：泛型不是“用 `T` 替换 `any`”，而是在函数的输入、输出、容器和约束之间**保留类型关系**。

## 一、泛型解决了什么问题？ ⭐⭐⭐

```ts
function identity<T>(value: T): T {
  return value;
}

const n = identity(42);          // 推导为 number
const s = identity('hello');     // 推导为 string
const b = identity<boolean>(true);
```

**对比 `any`**：`function identity(value: any): any` 会丢失输入输出关联；`<T>(value:T):T` 保留关联，支持调用时自动推导。

**面试高频**：什么情况下该用泛型，什么情况下直接用联合类型？——需要**关联多个位置的类型**时优先泛型，只需接受若干输入类型且返回固定结果时，联合类型往往更简单。

## 二、泛型约束 `extends` 与 `keyof` ⭐⭐⭐

```ts
function getProperty<T extends object, K extends keyof T>(
  obj: T,
  key: K,
): T[K] {
  return obj[key];
}

const user = { id: 1, name: 'Ada', active: true };
const name = getProperty(user, 'name');  // string
const id = getProperty(user, 'id');      // number
// getProperty(user, 'email');          // ❌ 类型不匹配
```

这里的 `K extends keyof T` 不只是限制参数，还让 `T[K]` 精确对应属性值类型。

**常见错误**：误以为 `T extends { length: number }` 意味着 `T` 必须是数组。实际上字符串、数组及自定义拥有数值 `length` 属性的对象都满足结构约束。

```ts
function getLength<T extends { length: number }>(value: T): number {
  return value.length;
}
getLength('hello');  // 5
getLength([1, 2]);   // 2
getLength({ length: 7 }); // 7
```

## 三、多个泛型参数与默认类型 ⭐⭐

```ts
type ApiResponse<TData, TError = string> =
  | { ok: true; data: TData }
  | { ok: false; error: TError };

function success<T>(data: T): ApiResponse<T> {
  return { ok: true, data };
}

const response = success({ id: 1, name: 'Ada' });
if (response.ok) {
  response.data.name; // string
}
```

**注意**：泛型默认类型不是“所有未传入的运行时参数都会自动得到默认值”，它只作用于**类型参数**。

## 四、泛型接口、类型别名与类 ⭐⭐

```ts
interface Repository<T> {
  findById(id: string): Promise<T | null>;
  save(item: T): Promise<void>;
}

class MemoryBox<T> {
  constructor(private value: T) {}
  get(): T { return this.value; }
  set(next: T): void { this.value = next; }
}

const box = new MemoryBox<number>(123);
box.set(456);
// box.set('wrong'); // ❌ string 不能传给 number
```

这里一个类型参数 `T` 同时约束多个操作，适合抽象服务层、缓存、列表组件、表单模型等。

## 五、在实际 API 封装中使用泛型 ⭐⭐⭐

**误区**：给 `fetch` 的结果写 `as T` 或定义 `request<T>()` 并不代表服务器数据已经经过验证。

```ts
async function requestUnknown(url: string): Promise<unknown> {
  const response = await fetch(url);
  if (!response.ok) throw new Error(`HTTP ${response.status}`);
  return (await response.json()) as unknown;
}

type User = { id: number; name: string };

function isUser(value: unknown): value is User {
  if (typeof value !== 'object' || value === null) return false;
  const obj = value as Record<string, unknown>;
  return typeof obj.id === 'number' && typeof obj.name === 'string';
}

async function getUser(url: string): Promise<User> {
  const raw = await requestUnknown(url);
  if (!isUser(raw)) throw new Error('Invalid user payload');
  return raw;
}
```

**关键**：类型注解负责“静态约束”，`isUser` 负责“运行时验证”。这里的例子展示核心思路，复杂业务可使用成熟的 Schema 校验库。

## 六、泛型与函数重载该怎么选？ ⭐⭐

- **泛型**：输入和输出存在可统一表达的类型关系，例如 `get<T,K extends keyof T>()`。
- **联合类型**：仅表达有限可接受类型、输出无需依赖具体输入时。
- **函数重载**：不同输入组合对应明显不同的返回值或调用签名，但统一泛型表达过于晦涩时。

```ts
function wrap<T>(value: T): { value: T } {
  return { value };
}
const wrapped = wrap('hi'); // { value: string }
```

## 七、最容易出错的地方

1. 泛型写得太多：只有一个参数又不与其他类型位置建立关系时，泛型可能没有意义。
2. 错把 `T extends X` 当成运行时继承：它是**类型约束**，不会生成继承关系。
3. 把 API 返回值直接断言为 `T`：断言不是校验。
4. 对泛型过度显式传参：能推导时通常更易维护。
5. 只写 `Array<any>` 会失去类型信息，优先使用 `Array<T>`。
