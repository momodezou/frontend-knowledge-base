# TypeScript 类型体操：高频基础题与实用递归类型

> **定位**：用少量代表性练习掌握类型运算的思维方式，而不是追求复杂题数。
>
> **学习路线**：`keyof` / `T[K]` → 映射类型 → 条件类型 → 联合分布 → `infer` → 递归类型。

## 一、先建立三个思维模型 ⭐⭐⭐

1. **联合类型是集合**：`'a' | 'b'` 表示值可属于多个候选类型之一。
2. **映射类型遍历属性键**：`[K in keyof T]` 类似在类型层面改造对象结构。
3. **条件类型可进行分支与推断**：`T extends U ? X : Y`，`infer` 用来提取结构里的类型。

开始前可以先回顾：[高级类型](./高级类型.md) 与 [工具类型](./工具类型.md)。

## 二、基础练习 1：自己实现 Pick / Readonly / Partial ⭐⭐⭐

题目：通过映射类型改造对象属性。

```ts
type MyPick<T, K extends keyof T> = {
  [P in K]: T[P];
};

type MyReadonly<T> = {
  readonly [P in keyof T]: T[P];
};

type MyPartial<T> = {
  [P in keyof T]?: T[P];
};

type User = { id: number; name: string };
type UserName = MyPick<User, 'name'>; // { name: string }
type ReadonlyUser = MyReadonly<User>;
type PartialUser = MyPartial<User>;
```

**要点**：`K extends keyof T` 限制允许的键，`T[P]` 获取属性对应类型，`readonly` / `?` 修饰符只影响类型检查。

**易错**：`MyPartial` 默认只做浅层可选，不会递归修改 `User['profile']`。

## 三、基础练习 2：Exclude / Extract / IsNever ⭐⭐⭐

```ts
type MyExclude<T, U> = T extends U ? never : T;
type MyExtract<T, U> = T extends U ? T : never;
type IsNever<T> = [T] extends [never] ? true : false;

type Status = 'idle' | 'loading' | 'done';
type Finished = MyExclude<Status, 'idle' | 'loading'>; // 'done'
type Ongoing = MyExtract<Status, 'idle' | 'loading'>; // 'idle' | 'loading'
type Check = IsNever<never>; // true
```

**为什么要写 `[T] extends [never]`？** 避免裸类型参数触发分布式条件类型；若直接写 `T extends never`，传入 `never` 时可能仍得到 `never` 而非想要的布尔类型。

## 四、基础练习 3：元组转联合、提取函数参数 ⭐⭐⭐

```ts
type TupleToUnion<T extends readonly unknown[]> = T[number];
type Element = TupleToUnion<readonly ['A', 'B', 'C']>;
// 'A' | 'B' | 'C'

type MyParameters<T extends (...args: any[]) => unknown> =
  T extends (...args: infer P) => unknown ? P : never;

type MyReturnType<T extends (...args: any[]) => unknown> =
  T extends (...args: any[]) => infer R ? R : never;

type Fn = (name: string, age: number) => boolean;
type Args = MyParameters<Fn>;   // [name: string, age: number]
type Result = MyReturnType<Fn>; // boolean
```

**要点**：`T[number]` 可以取得元组/数组所有元素类型的联合；`infer` 从函数类型里提取参数元组或返回类型。

## 五、进阶练习 4：Omit 与属性覆盖 ⭐⭐⭐

```ts
type MyOmit<T, K extends PropertyKey> = {
  [P in keyof T as P extends K ? never : P]: T[P];
};

type Override<T, U> = Omit<T, keyof U> & U;

type User = { id: number; name: string; active: boolean };
type WithoutActive = MyOmit<User, 'active'>;
type UserWithStringId = Override<User, { id: string }>;
```

**为什么不能直接用 `T & U` 覆盖字段？** 如果两侧属性类型冲突，交叉可能得到 `never`，而不是后者覆盖前者。

**备注**：此 `MyOmit` 的第二参数允许任意属性键；内置 `Omit` 的键类型约束也允许 `PropertyKey`，这是为了适应“删除不存在的属性也不出错”的场景。

## 六、进阶练习 5：DeepReadonly 与 DeepPartial ⭐⭐

题目：把嵌套对象的属性递归设为只读/可选。

```ts
type Primitive = string | number | boolean | bigint | symbol | null | undefined;

type DeepReadonly<T> =
  T extends Primitive | ((...args: any[]) => unknown) ? T :
  T extends object ? { readonly [K in keyof T]: DeepReadonly<T[K]> } : T;

type DeepPartial<T> =
  T extends Primitive | ((...args: any[]) => unknown) ? T :
  T extends object ? { [K in keyof T]?: DeepPartial<T[K]> } : T;

type Settings = {
  theme: { colors: { primary: string } };
  flags: string[];
};

type ReadonlySettings = DeepReadonly<Settings>;
type PartialSettings = DeepPartial<Settings>;
```

**重要边界**：此版本是教学用的简化实现。真实项目应明确处理 `Date`、`Map`、`Set`、复杂类实例、特殊函数、数组、元组、循环类型等。递归类型也受到编译器复杂度限制。

**面试时别只背代码**：要能解释为什么基础类型和函数需要作为递归终点，以及数组/元组的映射与对象字段映射有哪些区别。

## 七、进阶练习 6：事件名称映射 ⭐⭐

```ts
type Events<T> = {
  [K in keyof T as K extends string ? `${K}Changed` : never]: (value: T[K]) => void;
};

type FormModel = { name: string; age: number };
type FormEvents = Events<FormModel>;
// {
//   nameChanged: (value: string) => void;
//   ageChanged: (value: number) => void;
// }
```

**工程场景**：给表单模型生成一组类型安全的事件回调接口。

## 八、如何验证类型题答案？ ⭐⭐⭐

可以使用简单的类型断言工具，在编译时检查两个类型是否相等（这种常见写法适合多数练习，但并不表示覆盖所有复杂的 TS 类型等价关系）。

```ts
type Equal<X, Y> =
  (<T>() => T extends X ? 1 : 2) extends
  (<T>() => T extends Y ? 1 : 2) ? true : false;

type Expect<T extends true> = T;

type MyPick<T, K extends keyof T> = { [P in K]: T[P] };
type Test1 = Expect<Equal<MyPick<{ a: 1; b: 2 }, 'a'>, { a: 1 }>>;
```

通过 `tsc --noEmit` 检查；如果类型不相同，`Expect<true>` 的约束会使编译失败。

## 九、常见陷阱与面试追问

| 问题 | 理解要点 |
|---|---|
| `never` 为什么会使某些条件类型直接得到 `never`？ | 分布式条件类型作用于空联合 |
| `any` 为什么影响类型推导的可靠性？ | 会绕过或干扰正常的类型约束与推断 |
| 如何阻止联合类型分发？ | 用 `[T] extends [U]` 包装 |
| 类型体操越复杂越好吗？ | 否，过度复杂会增加理解与编译维护成本 |
| `DeepReadonly` 能阻止运行时改值吗？ | 不能，它是静态检查 |
